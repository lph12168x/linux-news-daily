Blender 5.3 发布：DLSS 4.5 Ray Reconstruction 降噪、Vulkan 后端转默认
图形 GPU
开源 3D 建模软件 Blender 5.3 正式发布。新版本引入 3D Gaussian Splats 支持，可从照片或视频重建 3D 场景，并支持从 PLY、SPZ、glTF 文件导入 Gaussian Splats；渲染方面新增 NVIDIA DLSS 4.5 Ray Reconstruction 作为全新降噪器，并加入对 NVIDIA RTX Spark 设备的支持。Cycles 渲染器的 Principled BSDF 着色器节点现已支持色散（dispersion）。最值得关注的是：Vulkan 后端在 Linux 与 Windows（Windows on ARM 除外）上转为默认，要求 Vulkan 1.1 及以上，官方表示其性能应优于 OpenGL 后端。
关注理由：Vulkan 默认化是 Blender 图形栈从 OpenGL 迁移的里程碑，对 Mesa 驱动（RADV/ANV/NVK）的真实负载覆盖会显著增加，Linux 图形栈质量将直接受益。

X.Org Server / XWayland 再公开 8 个安全漏洞，AI/LLM 协助发现
显示 display
在 AI/LLM 工具协助下，安全研究者再公开 8 个 X.Org Server 漏洞（同样影响 XWayland 代码），包括 EDID DS_RANGES 越界写（CVE-2026-109091）、XvShmPutImage 共享内存边界溢出（CVE-2026-109092）、XTestFakeInput Valuator 栈越界写（CVE-2026-109093）、XRes 请求大小溢出（CVE-2026-109904/109094）、glamor Xv 图像大小整数溢出（CVE-2026-109095）、XvPutImage 负数长度绕过（CVE-2026-109096）、XvQueryImageAttributes 负数大小回复（CVE-2026-109903）等。修复版本为 xorg-server-21.1.26 与 xwayland-24.1.15。
关注理由：LLM 辅助审计正让 X.Org 这类老旧代码库的漏洞披露速度明显加快，显示栈上跑 XWayland 兼容层的发行版应尽快升级；这也是 Wayland 迁移紧迫性的又一个注脚。

AMD EPYC 9006「Venice」SP7 正式上市：旗舰 9996 达 256 核 / 512 线程
计算 compute
AMD 宣布 EPYC 9006 系列 Socket SP7 处理器正式供货，OEM/ODM 系统今日开始出货，Phoronix 同步放出独立基准。旗舰 EPYC 9996 为 256 核 Zen 6C / 512 线程，基频 2.55GHz、加速 4.1GHz，1GB L3，默认 600W（可下调 400W），96 条 PCIe 6.0 通道，16 通道 DDR5-8000 RDIMM 或 MRDIMM-12800，1KU 定价 14,904 美元。双路平台合计 512 核 / 1024 线程。AMD 称对比 Intel Xeon 6980P「Granite Rapids」，HPC 负载领先 2.2 倍、NAMD 达 3.2 倍；对比上代 EPYC 9005「Turin」整数算力 2 倍、浮点 2.4 倍、内存带宽 2.7 倍。同日另有 EPYC 9686F（96 核 Zen 6、最高 5.3GHz）高频型号评测。SP8 版本与 9006X/9006LP 将于 2027 年分批跟进。
关注理由：Zen 6 服务器平台正式落地，GCC/LLVM 的 znver6 支持与内核补丁早已就绪；对数据中心 Linux 与 AI/HPC 负载而言，这是当前 x86 服务器性能的天花板。

x86 生态咨询组发布 ACE v2 与 AVX10.3 规范，GCC 补丁同步就绪
计算 compute
AMD 与 Intel 主导的 x86 Ecosystem Advisory Group 公布 ACE v2（AI Compute Extensions）与 AVX10.3 架构规范。ACE v2 在 ACE 基础上引入更低精度的 API：新增 4-bit 格式并扩展 8-bit 能力，同时支持 FP16/FP32/FP64 模式；AVX10.3 面向通用向量化补充：FP8↔BF16 互转、BF16→FP8 转换，以及 FP16/BF16→INT4 转换指令。规范全文已在 x86ecosystem.org 公开。Intel 编译器工程师已同步提交 ACE v2 与 AVX10.3 两组 GCC 补丁供评审。带 ACE v2/AVX10.3 的 CPU 预计 2028~2029 年登场。
关注理由：FP8/INT4 低精度指令链是 AI 推理在 CPU 上落地的关键路径；规范与编译器支持先行、硬件两年后到位，开源工具链这种「先发」节奏值得跟踪。

AMD 确认 Zen 7 EPYC「Florence」将带 ACE，Zen 8「Ravenna」已在开发
计算 compute
在 EPYC 9006 SP7 上市说明会上，AMD 透露了后续服务器路线图：第七代 EPYC 「Florence」（Zen 7）确认搭载 AI Compute Extensions（ACE）——即 AMD 与 Intel 在 x86 生态咨询组框架下的协作成果，还将采用下一代 MRDIMM 与 LPDDR 内存，预计 2028 年投产并使用新制程节点。第八代 EPYC 「Ravenna」（Zen 8）已在开发中，预计 2030 年亮相；值得注意的细节是幻灯片只写了「Zen 8」而没有像此前 Zen 5/6/7 那样提及「Zen 8C」小核变体。
关注理由：ACE 进入服务器主路线图意味着 x86 AI 指令扩展将跨代延续；Zen 8 未提 8C 变体若属实，可能是 AMD 服务器核心策略转向的信号。

AMD 主推 MEXT 内存分层软件：用 NVMe SSD 顶替 DRAM，支持 Linux 但不开源
计算 compute
在当前内存供应紧张、价格飙升的背景下，AMD 在 EPYC Venice 发布会上大力宣传今年收购 MEXT 公司获得的 AI 预测式内存分层技术：让 NVMe SSD 闪存扮演类似 DRAM 的角色，作为 EPYC 服务器的额外内存层，由 AI 引擎负责数据在 DRAM 与闪存层之间的智能放置与 promote/demote。AMD 强调其 Linux 内核模块「可在任何 Linux 系统上运行」，并附带 RAM 可观测性工具。但与 AMD 一贯的开放生态不同，MEXT 目前既不开源也不公开提供，仅通过客户/销售渠道授权获取。
关注理由：内存涨价潮下，SSD 分层扩容是务实的降本路线，思路上与 Linux 内核已有的 memory tiering 方案接近；不开源的专有实现能否被社区接受，值得关注后续走向。
