Linux 7.5 图形/NPU 驱动开始排队：AMDXDNA 持续加码、Panfrost 支持 Mali G68
图形 gpu
Linux 7.4 合并窗口刚开几天，drm-misc-next 的第一批 pull request 就已发往 DRM-Next，开始为年底启动的 Linux 7.5 周期储备特性代码，本周又提交了第二批。第一批包括：AMDXDNA（Ryzen AI NPU）驱动经 DRM fdinfo 接口上报 busy time；Panfrost 新增 Arm Mali G68 支持，并改进 GPU reset 处理与初始化；rockchip/dw-hdmi-qp 增加 HDMI 2.0 支持；多个桥接芯片驱动获得新的 HDMI 1.x 能力；VirtIO 主平面支持 ARGB8888 格式；另有多款新面板。第二批聚焦 AMDXDNA：驱动修复、BOE NE140WUM-N41 面板支持、新固件版本适配，以及更多 AMD AIE4 特性——包括电源模式读写、内核队列生命周期与内存布局、suspend/resume 等。AIE4 是 AMD 下一代 Ryzen AI NPU，近几个月驱动活动密集，预计随 Ryzen AI Zen 6 平台首发。
关注理由：7.5 周期刚拉开帷幕就能看到清晰的图形/NPU 主线：AMDXDNA/AIE4 是 AMD NPU 开源栈的主战场，Panfrost 扩大 Mali 覆盖、HDMI 能力补齐也直接影响显示链路；提前跟踪 drm-misc-next 排队内容可预判下个内核的功能边界。

AMD 发布 ROCm HRX Loom v0.1：一套编译栈同时面向 CPU、GPU 与 NPU
计算 compute
AMD 在 Advancing AI 大会上发布 Hyperloom（面向 agentic 工作负载优化）之后，其落地组件 Loom SDK v0.1 随即标签发布——这是 Loom 作为 ROCm HRX（HIP Runtime Extended）一部分开源后的首个正式版本。Loom 是专用编译器与 IR 栈，官方描述为：编译 kernel 与异步设备程序、链接模型程序，并针对 CPU、AMD GPU、AMD NPU 三类目标做特化，同一套创作与执行路径贯穿源码事实、目标事实、配置、正确性用例与编译报告。hrx-loom SDK 打包了编译器、运行时、Python API 与命令行工具：loom-fetch 安装模型程序与资产，loom-serve 加载产物卡片并通过 HTTP 提供服务。目标后端方面，支持 AMDGPU HSA 产物用于 GPU 执行、SPIR-V/Vulkan 用于可移植执行，x86 与 WebAssembly 后端仍在完善。可从 GitHub（ROCm/hrx-system）获取 v0.1，也可 pip 安装 hrx-loom。
关注理由：「一套 IR 特化到 CPU/GPU/NPU」直指异构算力编程的碎片化痛点，与 NPU 驱动生态演进方向高度相关；这是 ROCm 软件栈里值得长期跟踪的新变量，v0.1 已可动手实验。

NVIDIA Vera 单路 vs 双路实测：172 核扩展顺畅、单卡约 430W
计算 compute
Phoronix 补充发布 NVIDIA Vera 单路（1P）与双路（2P）对比测试：每颗 Vera 提供 88 个 Olympus 核心、开 SMT 后 176 线程，双路合计 172 核 / 352 线程。测试选用可扩展到高核数且对多路 NUMA 友好的负载，环境为 Ubuntu 24.04 LTS + Linux 6.17 64K 内核。结论「符合预期、没有意外」：1P 到 2P 在数十项基准的几何平均上扩展顺畅，未遇到可扩展性或 NUMA 问题；两档配置下 CPU 峰值频率保持一致（平均 3.2GHz、峰值 3.3GHz）；每颗 Vera 在该负载组合下平均功耗约 430~440W、峰值 535W。
关注理由：NVIDIA 以独立 CPU 直接切入数据中心 CPU 市场，双路扩展无坑对其 2P 服务器形态至关重要；~430W/颗的功耗数字也为数据中心容量规划提供了第一手参考。

RISC-V 用户拷贝优化改为运行时检测，随 Linux 7.4 合并
计算 compute
RISC-V 架构变更已合并进 Linux 7.4，其中最亮眼的是把「跳过软件对齐」的优化从编译期改为运行时检测。该优化由 Tenstorrent 在 7.3 引入：对原生支持快速非对齐内存访问的硬件，跳过 user copy 中的软件对齐步骤，实测带宽提升最高 11%。但 7.3 要求编译期内联该支持，无法在混合硬件环境的发行版通用内核中启用。7.4 将 HAVE_EFFICIENT_UNALIGNED_ACCESS 的检测移到运行时——内核启动时探测硬件能力，动态决定是否跳过软件对齐，发行版通用 RISC-V 内核从此也能吃到这波优化。同期合并的还有：crash hot-plug 支持、页表函数路径优化、上下文切换优化，以及「B」位操作扩展与 Zic64b 扩展加入 hwcap/hwprobe 上报。
关注理由：「编译期特化 → 运行时探测」是通用内核发行版化的经典套路，11% 的拷贝带宽提升对 memcpy 密集型工作负载是实打实的收益；hwprobe 扩展上报也值得 RISC-V 应用生态关注。

Linux 7.4 网络子系统：硬件 Pacing Offload 落地，BIG TCP 混合路径提速 70%
内核 kernel
Linux 7.4 网络改动随合并窗口就位。核心侧新增硬件 pacing offload：网络设备引入 pacing_offload 属性，将出向包的定时与间隔控制下放到 NIC/SmartNIC，IDPF 驱动率先接入。性能方面，BIG TCP 与非 BIG TCP 混合路径的吞吐改进带来最高 70% 的提升，另有 TCP/IP 缓存效率与争用削减优化；无线侧也有时延改进，WiFi Aware 与 WiFi 8 相关工作继续推进。驱动侧：Nebula Matrix NIX 驱动首发、Meta 第二代 NIC「MPNIC」合入，FBNIC（Meta 一代卡）支持大块 IO_uring 零拷贝接收缓冲；另有 Qualcomm PPE 支持 IPQ5424、STMMAC 支持多个新平台、Realtek RTW88 以完整驱动替换 staging 中的 rtl8723bs、蓝牙侧新增 MT7928 与 QCC2072 支持。
关注理由：硬件 pacing offload 与 RDMA/高性能网络方向直接相关——把发包节奏交给 NIC 是拥塞控制卸载的又一格拼图，IDPF 只是起点，后续主流数据中心网卡跟进值得盯；BIG TCP 混合路径 70% 的吞吐收益对大流量场景同样关键。

Fedora 45 定档 11 月 3 日：Go/No-Go 通过，GNOME 51 + DRM Panic 上车
内核 kernel
Fedora 45 在今日 Go/No-Go 会议上正式宣布 GO，定于 11 月 3 日（下周二）发布；此前两次因 RC 组装不及与 blocker bug 推迟，问题均已在过去一周修复。RC 1.4 安装镜像已被宣布为稳定版，与下周镜像一致，现在即可下载。功能亮点：引入 KMSCON 替代内核控制台、Anaconda 安装器支持 Stratis 存储、改进 Qualcomm Snapdragon X 笔记本支持、默认限制 ptrace、默认强制签名校验、包构建要求可复现，以及新增 DRM Panic 前端——内核出问题时能给出更友好的画面。软件版本：GNOME 51、Go 1.27、Python 3.15、GCC 16.2、Glibc 2.44、LLVM 23、RPM 6.1。
关注理由：DRM Panic 与 KMSCON 都是图形栈用户可感知的体验升级，ptrace 限制与签名强制则改变桌面安全基线；作为 GNOME 51 / LLVM 23 / GCC 16.2 的首发载体，Fedora 45 是下个月值得第一时间升级的发行版。
