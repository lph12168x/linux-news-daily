Mesa 26.3 正式发布：RADV 适配 VK_AMD_anti_lag、Intel Jay 着色器编译器转默认、NVK 迎来 Vulkan Video
图形 GPU
Mesa 26.3 作为第四季度特性版本正式发布，是本季开源 OpenGL/Vulkan 驱动的重磅更新：
· RADV 新增 VK_AMD_anti_lag 支持——AMD 抗延迟扩展落地开源驱动，对竞技类游戏输入延迟优化直接有效；同时改进早期 GCN 时代 GPU（Polaris 一代）的可靠性；
· Intel 侧：全新 Jay 着色器编译器默认启用，Nova Lake 图形由实验转为默认启用并支持 Nova Lake P 64 位 GPU 模式，另为 DXVK 游戏场景启用 buffer compression 提升性能；
· NVK（NVIDIA）驱动加入 Vulkan Video 支持；
· ARM/嵌入式侧大幅推进：panvk v6/v7 升级 Vulkan 1.3 并补齐 maintenance4~8 等一批扩展，Panfrost/PanVK 新增 Mali G68、G715、G615 支持，etnaviv HALTI5 达到 GLES 3.0，Turnip 新增 VK_QCOM_rotated_copy_commands；
· 还有 AND GFX1171 GPU 支持、radeonsi 的 EGL_NV_context_priority_realtime 等大量变更。
关注理由：季更的 Mesa 特性版本是开源图形栈的风向标：VK_AMD_anti_lag 进 RADV 意味着 NVIDIA 之外的 Anti-Lag 场景补齐；Intel Jay 编译器转默认与 Nova Lake 转正是 Intel 新平台 Linux 图形就绪的信号；NVK 补上 Vulkan Video 则让 NVIDIA 开源驱动的媒体能力短板开始收敛。

AMDGPU 内核驱动首批 GFX13 补丁现身：8 个补丁超 1.26 万行代码，指向下一代 RDNA 5
图形 GPU
继年初 AMDGPU 的 LLVM 后端 GFX13 补丁之后，AMDGPU Linux 内核图形驱动的 GFX 13 / GC 13.x 使能补丁今天正式出现在邮件列表：
· 由 AMDGPU 维护者 Alex Deucher 发出，共 8 个补丁、超过 1.26 万行代码（还不含常规的海量头文件）；
· 包含 GFX 13.0.1 与 GFX 13.0.4 两个具体目标的支持；
· 从补丁内容暂时看不出 RDNA 5 的新特性或能力细节，后续补丁才会逐步接通新功能；
· 按时间推断 GFX13 支持将进入 Linux 7.5 内核——内核中已有 Display Core Next 6（DCN6）等预计构成 RDNA 5 GPU 的 IP 模块。
关注理由：内核侧 GFX13 基础使能补丁是 RDNA 5 驱动工作的正式启动信号，与年初 LLVM 后端补丁形成完整链路。「先上 IP 基础使能、后续补丁再接特性」的 bring-up 节奏，以及 12.6k 行的首批体量，对自研加速器驱动的内核接入规划是很好的参照。

Intel ANV 落地 AV1 编码码率控制：Igalia 持续补强 Vulkan Video，Mesa 27.0 可期
显示 display
Igalia 的 Hyunjun Ko 持续为 Mesa ANV 驱动补强 Vulkan Video 支持。最新合入（目标 Mesa 27.0）的是 AV1 视频编码的码率控制（bitrate control）能力：
· Intel 官方对 ANV 的 Vulkan Video 投入不多（更倾向 VA-API 媒体驱动 + oneVPL 路线），开源生态侧主要靠 Igalia 推进；
· 新的 AV1 编码码率控制目前仅支持 Gfx12.5 一代硬件（对应 DG2/Alchemist、Meteor Lake 一代），且需要系统加载 HuC 微控制器固件；
· 期望后续扩展到更新的 Xe2 / Xe3 硬件，让 Vulkan Video 的 AV1 编码覆盖面扩大。
关注理由：Vulkan Video 作为跨厂商统一的视频加解码 API，是 FFmpeg/GStreamer 等多媒体栈的长期方向；码率控制是编码可用性的关键一环（此前 8 月 ANV 已在 DG2 上启用 VK_KHR_video_encode_av1 基础编码）。「厂商不投入、社区接棒」的 Igalia 模式也值得开源协作策略参考。

Linux 主线内核补丁 bring-up 三星 Galaxy XR 头显与高通 Snapdragon XR2+ Gen 2「Halliday」SoC，17 个补丁由多个 LLM 协助完成
显示 display
三星 Galaxy XR 头显默认运行 Android XR（自带下游内核补丁），本周开发者 Stanislav Aleksandrov（亦参与 KDE Plasma XR/VR 支持）发出初始补丁集，让该头显在主线内核上启动：
· 同时 bring-up 高通 Snapdragon XR2+ Gen 2（代号 Halliday）SoC——该头显的算力平台；
· 共 17 个补丁，主要内容是高通 Halliday 与三星 Galaxy XR 的初始 Device Tree 支持，作者称已在 Galaxy XR 实机上完成评审与测试；
· 目前可将头显启动到 initramfs 并通过 USB NCM 获得一个 shell；PCIe 与 WiFi 的使能补丁仍待跟进；
· 值得注意的是，这批补丁是在 Claude、ChatGPT、Gemini 三个 LLM 的协助下完成的。
关注理由：XR 头显这类高度定制设备走上主线内核，是 Linux 显示/外设生态向 XR 延伸的风向标；Device Tree bring-up 的最小可行路径（initramfs + USB NCM shell 优先，PCIe/WiFi 后补）是标准的硬件使能节奏。此外「三 LLM 协助完成内核补丁」是 AI 辅助内核开发落地的又一实例。

Firefox 160 发布：Web Speech API 端侧实时语音转文字（支持 40 种语言）、MKV 容器播放 FLAC/MP3/PCM 音频
显示 display
Firefox 160.0 稳定版发布，双周例行更新中的两个亮点都与媒体体验相关：
· Web Speech API 的语音识别（speech recognition）部分落地：支持端侧（on-device）实时语音转文字，覆盖 40 种语言——语音处理在本地完成而非云端；
· 新增 Matroska（MKV）容器播放支持，覆盖 FLAC、MP3、PCM 音频轨（一年前的需求评估还认为 MP3+Matroska 用量太低不在计划内，最终还是实现了）；
· 画中画（Picture-In-Picture）播放器新增语音播放速度设置，0.25x ~ 2.0x 可调；
· UI 细化：地址栏域名与路径的对比度提升。
关注理由：浏览器端侧 STT 是本地 AI 能力进入 Web 标准接口的标志性一步——对嵌入式/显示端设备的离线语音交互方案有直接参考价值；MKV 容器支持则补齐了本地媒体播放的一个常见格式缺口。
