KDE Plasma 6.8 正式发布：恰逢 KDE 项目 30 周年，Wayland 打磨成为主线
显示 display
KDE Plasma 6.8 正式发布，与 KDE 项目 30 周年重合（1996 年 10 月项目启动）。这是一个特性密集且打磨充分的版本：
① vRAM 占用优化（Breeze 主题引擎省显存）；
② KWin 支持 Wayland commit-timing 协议——视频播放与 Adaptive-Sync/FreeSync 场景的呈现时序可控；
③ 多 GPU 处理改进与多显示器改进，新增 kscreenctl 显示配置工具；
④ 服务端投影阴影（server-side drop shadow）支持、Wayland 下 dwell clicker（悬停点击）支持；
⑤ 远程桌面支持增强（KRDP 低延迟方向延续）；Union 主题引擎改进。
值得一提的是，发布前最后一刻还修掉了 NVIDIA 专有驱动下窗口平铺卡顿的问题（Qt 改用单一持久 OpenGL 上下文）。Wayland 角度的微调与打磨贯穿整个 6.8 周期。
关注理由：Plasma 6.8 是 Wayland 桌面成熟度的又一个里程碑：commit-timing 协议、多 GPU/多屏改进、服务端阴影——这些正是过去半年里 KWin 逐个合入的特性在正式版的汇总。
30 周年节点 + 这批图形栈改进，值得作为评估 Plasma 6.8 升级与 Wayland 迁移的参考版本；对做显示/合成器方向的同学，KWin 的 commit-timing 与多 GPU 路径尤其值得过一遍代码。

Epic Games 改进 Linux 反作弊：EAC Linux v2 走 systemd 服务 + eBPF，弃内核模块
内核 kernel
Epic Games 宣布 Easy Anti-Cheat（EAC）Linux v2——对 Linux 反作弊方案的彻底重构，同时官宣 Epic Games Launcher 预览版（含 Linux 支持）与《堡垒之夜》官方 Linux 支持的推进。
EAC Linux v2 的技术路线很克制：不再依赖 Linux 内核模块，而是：
① 反作弊 systemd 服务——运行受保护游戏时启动，游戏结束后可卸载；
② eBPF 内核程序承担安全功能；
③ 依赖 UEFI Secure Boot，信任链由 Canonical、Fedora、Universal Blue、Debian、SUSE、Rocky Linux 或 Microsoft UEFI CA 签发的密钥保证。
注意：Steam Deck 暂不支持 EAC Linux v2 所需的功能，Epic 正在与 Valve 合作解决。
关注理由：这是主流游戏厂商在 Linux 上第一次放弃内核模块路线、转向 eBPF + systemd 的官方反作弊——对「Linux 桌面游戏生态」是标志性事件：EAC v2 + Epic 启动器 + 堡垒之夜，等于把 Linux 挡在门外的最后几个大作之一拉了回来。
技术上看，eBPF 承载安全策略 + Secure Boot 建立信任链的组合，对内核安全、容器/沙箱方案也有参照意义；Steam Deck 的兼容缺口则是后续值得跟踪的点。

Ubuntu 26.10 amd64v3 包在 AMD EPYC 上实测：平均小幅领先，特定负载收益可观
计算 compute
Phoronix 用 Gigabyte MZ33-AR1 + EPYC 9555P（64 核）实测 Ubuntu 26.10 的非官方 amd64v3 软件包仓库（按 x86_64-v3 微架构特性级别编译），200+ 项基准：
① 几何平均仅「略微更快」，但特定性能敏感负载收益明显：GNU Radio、部分 Python 操作、SPECFEM3D、Incompact3D 等科学计算代码优势可观；
② PostgreSQL 各配置略有改善，ClickHouse 官方包在 amd64v3 上也略有利好；
③ CPU 功耗无可测量差异——纯赚不亏。
Ubuntu 26.10 已开始构建 amd64v3 ISO 方便安装，但 Canonical 尚未正式把 amd64v3 作为通用 amd64 的替代品 endorsing；值得观察 Ubuntu 28.04 LTS 时是否正式支持甚至替换。
关注理由：x86_64-v3（AVX2 基线）编译是发行版层面最廉价的「免费性能」来源：不改代码、不加功耗，服务器平均小幅提升、HPC/信号处理等向量化敏感负载大幅受益。
对部署 EPYC 服务器跑计算负载的场景，amd64v3 仓库已到可评估阶段（注意其仍非官方支持）；若 Ubuntu 28.04 LTS 转正，这一选择将影响几乎所有企业部署基线。

Linux 内核将一键回答「这台 RISC-V 机器支持 RVA23 吗」
内核 kernel
RISC-V 的 RVA23 配置档对减少生态碎片化至关重要（现代 Ubuntu 已强制要求 RVA23），但用户此前想确认自己的系统是否合规，只能对每个强制扩展逐一发起 hwprobe / prctl 查询——一直没有一次性判定的方法。
高通工程师 Guodong Xu 的补丁系列正在补上这个缺口：通过 hwprobe 直接暴露 RVA23U64 基线行为，并同步体现在 /proc/cpuinfo 与 hwprobe 接口，用户态一条查询即可判定。
该工作在布拉格 LPC 2026 上进一步讨论；补丁系列的大部分已排队进 RISC-V 的 for-next 分支、目标 Linux 7.4，RVA23U64 位上报部分还在返工、至少还需一轮评审。
关注理由：RVA23 是 RISC-V 软件分发的「x86_64-v3 时刻」：只有硬件基线可一键检测，二进制分发才能落地。这条补丁把「逐扩展拼凑判定」变成「一条 hwprobe」，对 RISC-V 发行版（Ubuntu RISC-V 桌面镜像已落地）、容器与二进制分发工具链都是基础设施级改进。
对关注 RISC-V 服务器/加速卡生态的同学，7.4 的 RISC-V for-next 分支值得跟一下。

Apple 向 LLVM/Clang 上游贡献 SSAF 驱动：全程序分析与源到源转换
计算 compute
Apple 编译器工程师向上游 LLVM/Clang 贡献了 clang-ssaf-driver（Scalable Static Analysis Framework 驱动），用于全程序（whole-program）分析与源到源（source-to-source）代码转换，已合并进 LLVM Git。
工作方式：在项目构建过程中对整个工程运行源转换，最终产出补丁文件（冲突的编辑不进补丁）与转换报告（按编译器诊断风格打印，也可输出 SARIF）；支持 --apply 直接用 clang-apply-replacements 应用编辑并校验。
首个转换规则是 cpp-bounded-buffers：把需要边界检查的 C++ 裸指针与数组重写为 bounded_ptr / bounded_array。项目经 make 构建的可用 clang-ssaf-orchestrator-make 驱动。
作者 Apple 的 Jan Korous 说明这是此前提出的 clang-reforge 的泛化——目标是做一个与具体转换解耦的通用分析/转换驱动。预计随 LLVM 24（明年春季）发布。
关注理由：大规模 C/C++ 代码库的机械化安全改造（如裸指针 → 有界类型）一直缺趁手工具；SSAF 把「构建过程 + 全程序分析 + 自动补丁」做成通用驱动，思路类似 Rust 生态的迁移工具（cargo fix / 后续 edition 迁移器）。
对内部有大型 C/C++ 遗留代码、想做内存安全加固的团队，LLVM 24 的 SSAF 值得提前关注——这也是继 Apple 持续投入 Swift/工具链后，又一次把内部基础设施开源上游的案例。

Framework 对 CachyOS 的月度资助增至三倍（约 $850/月）
桌面
Framework Computers 宣布把对 CachyOS（基于 Arch Linux、以开箱即用性能调优见长的独立发行版）的月度捐赠从 $250 提高到约 $850——增至三倍。
此前 Framework 已向 CachyOS 提供硬件设备用于优化支持；新增资金将用于构建服务器、镜像与基础设施，并投入更多时间做性能优化。
背景：CachyOS 在最新 Steam 硬件调查中是占比最高的 Linux 发行版（约 18% 的 Linux 游戏系统），凭借面向性能的默认配置在 Linux 游戏玩家中广受欢迎。
关注理由：硬件厂商持续资助性能导向发行版（此前 Framework 也资助过发行版生态）是「Linux 游戏市场已被认真对待」的又一个信号——Steam 调查里 18% 的份额说明性能调优版 Arch 已成 Linux 游戏的事实选择之一。
对普通用户：若在选 Linux 游戏桌面，CachyOS 的构建优化（x86-64-v3/v4 软件包、调度器调优）与 Ubuntu amd64v3 的方向一致，与本条 amd64v3 评测可对照阅读。
