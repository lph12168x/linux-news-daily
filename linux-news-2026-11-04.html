Linux 7.4 特性总览：史上最大合并窗口，Steam Frame VR 头显初步支持、AMD Zen 6 就绪与 Apple M4 / A18 Pro 初始 bring-up
内核 kernel
Linux 7.4 合并窗口为内核历史上最大，有望成为今年 LTS。图形/显示侧重点：
· AMDGPU 默认启用 HDMI 2.1——HDMI VRR/FreeSync 与 ALLM 已就绪，Radeon 用户高刷/高分 HDMI 显示器终于无需手动开启；
· AMD PerfOpt 默认启用，为 Radeon iGPU 的 AI/LLM 负载提供更好性能；
· Steam Frame VR 头显获得初始支持（基础 Device Tree）；
· Intel Xe 驱动新增 CPU binds 与迁移队列上的 ULLS，并加入 vRAM 健康检查与显存降级处理；
· Qualcomm MSM DRM 支持 Adreno A830/A845/A850/X2-85；NVIDIA Nova Rust 驱动继续推进。
CPU/平台侧：Zen 6 客户端支持就绪（含 BTB CTX 隔离降低安全缓解开销）、Apple M4/A18 Pro 初始支持（尚未可用）、Google Tensor G5 主线支持、内存侧 memblock 早期分配器从约 265 秒加速到约 50 毫秒。
关注理由：7.4 大概率是年度 LTS，本期特性将影响未来一两年的部署基线。对图形/显示/计算方向而言，AMDGPU HDMI 2.1 默认化与 Xe 驱动的 CPU binds/ULLS 是最直接的用户可感改进；Steam Frame VR 初始支持则标志 Valve 自家 VR 硬件正式进入主线内核轨道。

Fedora 45 正式发布：KMSCON 取代内核控制台、DRM Panic 前端上线，GNOME 51 + Linux 7.2
发行版 distro
两度延期后 Fedora 45 正式发布。与显示栈直接相关的变化：
· 引入 KMSCON 取代内核自带控制台；
· 启用 DRM Panic 前端——内核出错时呈现更友好的画面（类似 Windows 蓝屏的 DRM 级图形化 panic 界面）；
· Anaconda 安装器支持 Stratis 存储；
· 默认限制 ptrace、默认强制签名校验、要求软件包构建可复现。
软件栈：GNOME 51、Python 3.15、GCC 16.2、LLVM 23、Glibc 2.44、RPM 6.1；出厂内核为 Linux 7.2，7.3 更新即将推送。
关注理由：Fedora 是上游新特性落地最快的头部发行版，其选择往往预示技术风向：DRM Panic 与 KMSCON 表明「内核图形栈接管启动/故障显示」路线进一步巩固，ptrace 限制与可复现构建则是桌面安全与供应链方向的标志性默认值。对评估图形栈新特性落地节奏很有参考价值。

RadeonSI 与 RADV 为 GFX8 时代 GPU 启用 D16 支持：RX 470/480/570/580 老卡再获 DX12 性能优化
图形 GPU
Valve Linux 图形团队工程师 Georg Lehmann 向 Mesa 提交 17 个补丁，为 AMD GFX8 架构显卡启用 D16 数据格式支持，已合入 Mesa 27.0 开发分支，同时惠及 RadeonSI（OpenGL）与 RADV（Vulkan）。要点：
· D16 是 16 位数据修饰符，可在加载/存储指令中用打包的 16 位数值替代 32 位，核心价值是降低显存带宽压力、提升寄存器利用效率；
· 此前开源驱动仅对 GFX9 及更新架构启用 D16，GFX8（GCN 火山岛到 Polaris 系列）一直无缘；
· 关键背景：GFX8 硬件已通过 VKD3D-Proton 获得全部 D3D12 内容的 FP16 支持，D16 补齐后老卡在 Linux 下运行 DX12 游戏可更高效处理 16 位深度与色彩数据。
关注理由：AMDVLK 官方 Vulkan 驱动早已停止支持 GFX8，开源社区却在持续为七年老硬件挖掘性能——这正是 Mesa 开源驱动相对闭源栈的长期价值所在。对关注驱动优化的团队亦有方法参考：利用硬件已有的打包修饰符做带宽优化，是低成本高收益的典型手段。

Intel Compute Runtime 26.40 发布：GPU D Series（Crescent Island）默认启用共享 USM，Nova Lake P 默认走 OpenCL LEO
计算 compute
Intel Compute Runtime 26.40.40196.8 发布（Windows/Linux 双平台开源 GPU 计算栈）：
· Crescent Island AI 加速器（现名 Intel GPU D Series）支持继续就绪——共享系统统一内存 USM 默认启用，GPU kernel 可通过 C/C++ 指针直接访问普通 CPU 系统内存；Defer backing 亦默认启用；
· Standby 模式能力在搭配 Xe 内核驱动时对 Battlemage 与 Crescent Island 启用；
· 性能优化：改进多队列使用、增大可用的本地内存环形缓冲区容量；
· OpenCL LEO（Level Zero Executing OpenCL，即在 Level Zero API 之上重新实现 OpenCL）对 Nova Lake P 默认启用，不再维护专用 OpenCL 硬件驱动实现；
· 另有前端复制能力、实验性 event flags 扩展及 Level Zero 编译优化重构。
关注理由：USM 共享内存默认化显著降低 GPU 计算程序的开发门槛（无需显式管理 host/device 拷贝），而 OpenCL LEO 路线意味着 Intel 计算栈正在收敛到 Level Zero 单一硬件抽象层——维护面收窄、迭代加快。对 NPU/加速器方向的驱动与运行时设计均有借鉴意义。

Domicile Desktop：用 Chromium 把 Wayland 原生窗口变成 DOM 元素，Web 开发者可用 HTML/CSS/JS 定制整个桌面
显示 Wayland
新项目 Domicile 是一个基于 Chromium 的 Wayland 合成器，让开发者用 HTML、CSS、JavaScript/TypeScript 构建 Linux 桌面：修改版 Chromium 引擎将原生 Wayland 窗口表示为 DOM 元素，开发者可像排版普通网页一样对窗口进行样式化、变换、动画与组织。合成器侧采用 Sway 风格、Rust 编写的 Maganese 平铺代码。项目官网 Domicile-Desktop.com，且确认是与 AI（Claude Code）协作开发。
关注理由：Web 技术进桌面并非新话题（Electron 应用泛滥已久），但「合成器本身就是 Chromium、窗口即 DOM」是更激进的路线：窗口管理获得了 CSS 动画/变换的全部表达能力，定制门槛从 C/Rust 降到前端技能栈。观点必然两极分化（性能/内存开销 vs 定制亲和性），作为 Wayland 生态的实验性方向值得观察。

GIMP 3.2.8 发布：多项 GUI 细节改进，因 AI 扫描工具带来的海量安全报告而修复一批安全问题
显示 Desktop
GIMP 3.2.8 稳定版发布：
· 取色显示 GUI 改进，编辑时可看到更细微的颜色变化；
· 更新 HEIF 加载代码，可加载更大的 HEIF 图像；
· 新增 GUI 自动化测试套件，用于开发期回归检查；
· 字体加载代码可提前取消，改善程序关闭速度；
· 主题文件补充更多定义，各平台外观一致；
· 改进 AppImage 兼容性。
安全方面：因「软件扫描与测试工具的最新进展」带来大量安全报告，本版包含多项安全修复。GIMP 团队说明：最常见的报告是旧图像插件与遗留滤镜过度信任图像文件提供的尺寸信息，恶意篡改可致插件（而非 GIMP 本体）崩溃，不涉及个人数据泄露。
关注理由：GIMP 是 Linux 桌面图形处理的旗手，本版值得关注的有两点：一是自动化 GUI 测试套件的引入（成熟桌面应用补测试基建的典型动作）；二是与 RADV 立规、内核 EDAC 退役、FreeRDP 补丁版同一条主线——AI 驱动的自动化扫描正在给上游项目制造真实的安全报告与维护压力，各项目应对策略开始分化。
