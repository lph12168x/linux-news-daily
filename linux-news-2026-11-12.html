Intel 持续为 Linux 7.5 使能 GPU D-Series「Crescent Island」：HWMON 温度传感、RAS CPER、ECC
图形 GPU
Xe3P 架构 AI 加速器「Crescent Island」已定名为 Intel GPU D Series，面向 Linux 7.5（2027 年首个稳定内核系列）的驱动使能持续推进。最新 drm-xe-next 拉取请求为 Xe 硬件监控（HWMON）落地温度传感器处理：平台报告的 VRAM 热通道、PCIe 与内存控制器温度等；同时加入 RAS 错误的 CPER（Common Platform Error Record）日志支持、OOBMSM telemetry「OCode」late binding，以及内存 double-bit ECC 错误处理。
Intel 自去年 10 月发布 Crescent Island 后数周即开始推送驱动补丁，至今已持续一年多。
关注理由：D-Series 是 Intel 在 GPU 计算市场的关键落子，HWMON / RAS / ECC 这类数据中心级运维能力进内核，意味着该产品线已从「预发布使能」转向量产级质量；对关注自研加速器平台软件栈的团队有直接参考价值。

AMD RDNA5/GFX13 初始代码进入 Mesa：RADV 与 RadeonSI 双驱动起步
图形 GPU
继本周早些时候 AMDGPU 内核驱动的 GFX13 补丁之后，AMD 今日为 Mesa 开出合并请求，为 RADV（Vulkan）与 RadeonSI（OpenGL / Gallium3D）引入最初级的 GFX13 支持——业界普遍认为 GFX13 即下一代 RDNA5 GPU。
该 MR（!46171）包含初始 GFX13 支持以及 RadeonSI 和 RADV 的芯片 ID 与描述符变更；未来数周至数月还将有后续 MR 补齐更多硬件使能，包括 ACO 编译器后端改动与寄存器支持。新一代 AMD Radeon 显卡预计 2027 年晚些开始出货。
关注理由：从内核侧到 Mesa 用户态的全栈铺开节奏看，RDNA5 的 Linux 支持启动时点比上一代更早；对预判下一代 AMD GPU 开源驱动成熟曲线、研究早期使能基线（芯片 ID / 描述符布局）很有价值。

EPYC 9006「Venice」vs NVIDIA Vera HPC 实测：9686F 2P 领先 1.13 倍、旗舰 9996 达 1.18 倍
计算 compute
继昨日 Venice SP7 上市评测之后，Phoronix 补上了与 NVIDIA Vera CPU 的 HPC 对比：Venice 在 Ubuntu 26.10 + Linux 7.3、双方同为 GCC 15 的环境下单独重测（Vera 数据复用上月基准）。
结论：以 HPC 为主的负载几何平均下，EPYC 9686F 2P 达 Vera 2P 的 1.13 倍——尽管其 176 核少于 Vera 双路的 192 核，单核性能同样胜出；256 核 Zen 6C 旗舰 EPYC 9996 达 1.18 倍。Coremark 上 Venice 对 Turin 大幅领先且能效最佳；7-Zip 压缩 Venice 领先，解压则是 9996 2P 最好、Vera 2P 次之。libxsmm 特化稠密/稀疏矩阵运算中，Vera 仅在小尺寸矩阵占优，矩阵规模增大后 Venice / Turin 反超。Venice 整机功耗高于 Vera，但典型负载下 perf-per-Watt 更优。换用 GCC 16（首个带 Znver6 目标的版本）或新发的 AOCC 6.0 还有进一步提升空间。
关注理由：这是 x86 服务器 CPU（EPYC Zen 6）与 NVIDIA 首款自研服务器 CPU（Vera / Olympus，Arm）的正面对决，HPC 场景 Zen 6C 明显占优；对服务器选型与竞品对标（性能 / 功耗口径统一、同编译器对照）是难得的同源数据。

AMD AOCC 6.0 随 EPYC Venice 同步发布：首轮 Zen 6 调优、全新 aof Fortran 编译器、aoc / aoc++ 品牌
计算 compute
随 EPYC 9006「Venice」上市，AMD 发布自研 LLVM/Clang 系编译器栈 AOCC 6.0：首轮 Zen 6 调优（面向 EPYC 9006 系列，含 AOCL-LibM 6.0），可作为上游 LLVM/Clang 与 GCC 中 znver6 支持之外的替代。
两个看点：一是引入全新 Fortran 编译器 aof——AMD 称其为 AOCC Fortran 的未来方向，对最新 Fortran / OpenMP 标准的一致性更好，目前与上游 LLVM Clang 代码同级（旧 Flang 仍随 6.0 提供）；二是编译器二进制首次品牌化：C 编译器命名 aoc、C++ 为 aoc++（clang / clang++ 以符号链接兼容保留）。AOCC 6.0 基于 LLVM 21.1.8——未能采用最新 LLVM 22/23 系列略显遗憾。
关注理由：aof 与 aoc / aoc++ 品牌化说明 AMD 正把 AOCC 从「内部工具」往正式产品线经营；Zen 6 编译调优与处理器发布当日同步落地的节奏，对 HPC / 推理部署侧的编译器选型有参考意义。

24 年老卡仍在进化：ATI R300~R500 获 2026 年 Mesa 着色器编译器优化
图形 GPU
已 24 岁的 ATI Radeon R300 系 GPU 本周继续收到改进：一批着色器编译器优化合入 Mesa 27.0-devel，惠及 R300、R400 与 R500（Radeon X1000 系列）。
长期几乎单人维护 R300g 驱动的 Pavel Ondračka 本次提交「一批小与较大的编译器改进」：指令配对（pairing）、omod 与 presubtract 调整、dp2 优化等，其中不少灵感来自对老 Catalyst 驱动（Radeon GPU Shader Analyzer）dump 的逆向比对，最具代表性的是 CMP movs 合并技巧。实测 RV370 总指令数下降约 3%，cycles / temps / consts 各有百分之几的降低；R420 与 RV530 也有几个百分点的收益。
关注理由：一人长期维护 24 年前的硬件仍有实际性能收益，是开源驱动生命周期的经典样本；其「对照官方编译器输出做优化」的方法论，对自研 shader compiler 的调参与验证同样可借鉴。
