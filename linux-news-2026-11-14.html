Wine 11.22 发布：ARM64 上 x86 模拟新增 AVX 支持，Wine 12.0 临近
显示 display
Wine 11.22 双周开发版发布，距离 Wine 12.0 稳定版准备阶段越来越近。最大亮点是 Wine ARM64 的 x86 模拟路径新增 AVX（Advanced Vector Extensions）支持：现代 Windows 软件普遍假设 AVX 存在，现在可通过 ARM64EC 构建得到良好模拟，此前已有 NTDLL for AVX on ARM64EC 与 XState 处理等铺垫 MR。其他更新：locale 数据升级到 Unicode CLDR 49、新增地址空间随机化、Tahoma 字体 glyph metrics 改进、XML DTD 校验重写；共修复 34 个已知 bug（Guild Wars 2、Star Citizen、Logos Bible Software 等）。
关注理由：对 ARM Linux 桌面（如 Snapdragon X 笔记本）而言，AVX 模拟是跑现代 Windows 游戏与应用的关键拼图；Wine/Proton 在 ARM64 上的能力边界直接决定 ARM 生态的游戏兼容性走向。

Linux 7.5 将收编开源软 GPU「GlandaGPU」驱动（VHDL 设计 + FPGA/QEMU）
图形 GPU
本周 drm-misc-next pull request 最引人注目的是全新的 GlandaGPU 驱动将进入 DRM-Next、随 Linux 7.5 合并窗口收编主线。GlandaGPU 是几个月前 RFC 的开源软 GPU 核心设计：用 VHDL 编写、当前跑在 Cycle V 等 FPGA SoC 上，也可用 QEMU 模拟，无需 FPGA 硬件即可体验。定位是学习与开源演示——VGA 输出 640x480 + 2D 加速引擎，别指望游戏或生产力。同批还有 HyperV cursor plane 支持、Etnaviv 驱动支持 Allwinner T527 VIP9000 及若干面板更新。
关注理由：主线内核再添一个完全开源的 GPU 实现，对 GPU 微架构学习、DRM 子系统研究与开源硬件社区都有示范价值；也再次证明 drm-misc 对小众/实验性 GPU 实现的包容。

NVIDIA 晒 vGPU 上游化进展：Rust 驱动 Nova 承载数据中心 GPU 虚拟化
图形 GPU
KVM Forum 2026（温哥华）上，NVIDIA 工程师 Simon Song 介绍了把 vGPU（单卡切分共享给多 VM/容器）支持带入上游 Rust 内核驱动 Nova 的进展。过去一年持续推进、正在成形：Nova 的 vGPU 使能部分预计随 Linux 7.5 落地更多，内核侧全部对齐估计要到 Linux 7.6+；用户态配套 vgpu-tools 正在开发；更远期规划包括 vGPU 实时迁移、异构 vGPU 等高级特性。Nova 的定位是最终达到乃至超越现有 out-of-tree 闭源驱动与 largely reverse-engineered 的 Nouveau。
关注理由：Nova 是 NVIDIA 官方未来的主线内核驱动方向，vGPU 上游化意味着云/数据中心 GPU 虚拟化不再依赖闭源 out-of-tree 驱动，是 NVIDIA 开源战略的实质性节点，对云 GPU 池化与虚拟化架构有直接影响。

AMD openSIL 随 EPYC 9006「Venice」达成量产目标，开源代码一季度内放出
计算 compute
AMD 向 Phoronix 确认 openSIL（开源 CPU silicon init，替代传统 AGESA）已随第 6 代 EPYC「Venice」达成既定量产目标。AMD 明确表示「没有任何 Venice 平台在无 openSIL 的情况下启动过」——即 Venice 全面走 openSIL 路径而非可选项；开源代码将在正式发布一个季度内（约 3 个月）放出。Zen 5 时代 openSIL 已有 Coreboot/Dasharo PoC（MSI Ryzen 主板、Gigabyte EPYC 服务器主板）；EPYC 9006 参考主板继续采用 OpenBMC；Coreboot 版 EPYC 9006 服务器将视客户兴趣推进。
关注理由：固件开源的里程碑——从 Zen 5 PoC 到 Zen 6 量产，意味着 Coreboot/Dasharo 社区可以真正覆盖服务器平台；固件供应链安全与可审计性直接受益，值得服务器固件/平台工程团队关注。

Intel 提前两年提交 Razor Lake / Coral Rapids GCC 支持（AVX10.2 + ML-DSA 蝶形指令）
计算 compute
Intel 提交了 Coral Rapids（下一代 Xeon）与 Razor Lake（Nova Lake 继任者）的初始 GCC 使能补丁，预计随 GCC 17.1（2027 年初）合并，两款 CPU 至少 2028 年才出货——延续 Intel「编译器先行」的一贯传统。Coral Rapids ISA 清单确认支持 AVX10.2（而非刚发布的 AVX10.3/ACEv2，设计定型过早）、APX_F、AMX-FP8/TF32/MOVRS 等，并新增 AVX10_VPMLDSABFLYDQ（Packed ML-DSA Butterfly，面向后量子签名 ML-DSA 的蝶形运算指令）；Razor Lake 与 Nova Lake 的 ISA 特性一致。同批还有含 AVX10_BMM 的 AVX10.3 更新补丁。
关注理由：编译器生态先行是 Intel 的长期优点，保证产品上市即有平滑的 GCC/发行版支持；VPMLDSABFLYDQ 把 FIPS 204 后量子签名做进硬件指令，对密码学负载是明确信号。

AMD HRX Loom + AI agent：3~4 天把 50 个热门 LLM 移植到客户端 GPU
计算 compute
AMD 团队（Jeremy Fowers、Ben Vanik）用刚发布的 HRX Loom v0.1 配合 agentic AI 工作流，把 50 个热门 Hugging Face 模型（横跨 18 种架构）移植到 AMD 客户端 GPU，仅花 3~4 天，硬件为 Ryzen AI Max「Strix Halo」。性能上，32K token prompt 处理较 llama.cpp 的 ROCm 后端提速 1.5~2.1 倍、较 Vulkan 后端约 1.9 倍。配套 loom-skills 可为 Claude Code、Codex、Pi 等 agent 装备为 AMD 客户端 GPU 编写与部署优化模型程序的能力；HRX Loom 同时支持 CPU/NPU 执行，目前仍是实验项目（结果见 Loom-Fun GitHub 页）。
关注理由：「AI agent 负责模型移植」是新范式的直接样本——把新模型/小众模型快速带上自有硬件的能力差异将被大幅拉平；HRX 统一 GPU/CPU/NPU 的抽象层对 NPU 与异构计算方向都有参考价值。
