AMD RDNA5 / GFX13 初步驱动支持进入 Linux 7.5：GC 13 + GMC 13 + DCN6
图形 GPU
11 月 26 日，最新一轮 AMDGPU / AMDKFD 内核图形与计算驱动改动被送入 DRM-Next，目标是 Linux 7.5 合并窗口。最受关注的是 GFX13 的初始落地——本月初首次公开的 AMD GFC13 / GC 13 图形 IP 补丁，被普遍认为对应下一代 RDNA5 GPU；此轮拉取请求已把这块新一代图形控制器的初步使能工作铺好，不过仍被明确界定为非常早期、实验性的支持。除新图形控制器外，补丁还包含更新版的图形内存控制器 GMC 13 与 SoC v2.0 支持，以及面向 RDNA5 显示输出的 Display Core Next 6（DCN6） 进一步更新。其余改动以错误修复为主，初期的 GFX13 补丁并未披露太多新硬件特性细节。Linux 7.5 合并窗口约在 12 月底开启、2027 年 Q1 稳定发布；RDNA5 显卡据传要到 2027 年稍晚才正式上市。
关注理由：这是下一代 AMD GPU 开源栈的起跑信号：GC 13 / GMC 13 / DCN6 同时进入 DRM-Next，意味着图形、显存管理和显示三条线将一起演进。关注 AMD 图形栈或计划适配 RDNA5 的团队，应留意后续内核版本里的能力补全节奏。

Linux 7.4 为 Panther Lake 核显 Arc B390 带来实测增益：部分场景帧率大幅提升
图形 GPU
11 月 26 日，Phoronix 在 Dell XPS 14 DA14260（Core Ultra X7 358H「Panther Lake」）上，对比了 Ubuntu 26.10 自带内核与开发中的 Linux 7.4 Git 对 Xe3 核显 Arc B390 的影响。在 1920x1080 下，ElectroBench 的两个场景、GravityMark 的 OpenGL / Vulkan / Vulkan 光追三种渲染器均以 Linux 7.4 最快；2880x1800 的 DDraceNetwork（Vulkan）帧率提升非常显著，但帧时间波动也比 7.3 更大。Tesseract、Unvanquished（Ultra）同样由 7.4 领先；而 Unvanquished（Medium）、Xonotic（Low）、yquake2 与 VKMark（Mailbox）仍是 Ubuntu 26.10 原内核更快。整体属于幅度不一的正向收益——考虑到此前多个内核版本已持续优化 Panther Lake，这些增量是在已有基础上叠加的。
关注理由：对新硬件而言，主线内核迭代本身就能带来「免费」性能：多数 3D / 光追测试由 7.4 领跑，但个别负载反而回退，说明升级前仍需按自身工作负载实测，尤其是帧时间稳定性敏感的场景。

DXVK 3.2 发布：接入 VK_EXT_present_timing，改善全屏游戏帧节奏
显示 display
11 月 26 日，DXVK 3.2 正式发布。这是基于 Vulkan 实现 Direct3D 8 至 Direct3D 11 的兼容层，被 Valve 的 Steam Play（Proton）广泛使用。本版最突出的新特性是支持 Vulkan 扩展 VK_EXT_present_timing：在显示合成器与底层显卡驱动都支持、且游戏启用了 vsync 的前提下，DXVK 可借助呈现时序在全屏游戏或启用内置帧率限制器时获得更一致的帧节奏（frame pacing）。其余更新包括 VRAM 驱逐逻辑改进、D3D11 资源上传优化以及一批游戏专项修复，完整变更见项目 v3.2 发布页。
关注理由：呈现时序是连接图形驱动与显示链路的关键一环：把帧节奏交给标准的 Vulkan 时序机制，比在应用层靠延时 heuristics 更可靠。对关注低延迟、稳定刷新体验的显示/游戏栈，这是值得跟进的落地进展。

Intel Xe 驱动将在 Linux 7.5 支持 PCIe FLR：面向 SR-IOV 与定向错误恢复
内核 kernel
11 月 26 日消息，上周的 drm-xe-next 拉取请求中，Intel 为 Linux 7.5 准备的 Xe 内核驱动改动终于引入了 PCIe Function Level Reset（FLR） 支持。FLR 是一种标准化机制，可只重置单个 PCIe 功能而不影响同一设备上的其他功能或系统中其他 PCIe 设备，对虚拟化、SR-IOV 和定向错误恢复尤其有用。Linux 内核本身支持 FLR 已有多年，此次是 Xe 驱动首次接上。Intel 工程师 Raag Jadav 历时数月、经历十余轮代码评审才将该系列合入，并坦承首版实现仍是「half baked」——目前仅限于 GT 重新初始化，其他组件需后续补齐。同批次改动还包含经 IRQ 路由的非致命错误处理、显示代码从 stolen memory 到系统内存的透明回退，以及面向 Nova Lake P 与 Crescent Island 的 GuC 固件更新。
关注理由：FLR 是 GPU 虚拟化直通、SR-IOV 切分与故障隔离的基础能力：没有它，单个 function 出错往往只能整卡复位。Xe 补齐这块能力，对云上图形/推理资源池化与可靠性设计有直接影响。

F2FS 大 folio 支持进入 dev 分支，有望随 Linux 7.5 落地
内核 kernel
11 月 26 日，开发者 Nanzhe Zhao 近月推进的 F2FS 大 folio（large folios）工作已合入 F2FS 文件系统的 dev Git 分支，很可能在即将到来的 Linux 7.5 周期落地。该系列在 F2FS 的 buffered I/O 路径上，为大部分可读/写文件启用大 folio（压缩文件暂时除外），同时支持大于 0 的最小 folio order；通过以多页 folio 取代单页处理，可减少页级管理开销并带来性能收益，补丁系列中附有基准数据。同一 dev 分支还排入了另一组补丁：允许块大小小于内核页大小，使 ARM64 上 16K / 64K 内核页仍可使用 4K 块，且无需更改磁盘格式。
关注理由：大 folio 已从思想实验走进入主线候选：对 I/O 密集的计算负载和闪存存储栈，减少页级开销是实打实的收益；与前面几条 GPU / 显示改动合看，可以看出 Linux 7.5 在图形与底层 I/O 两条线上同步演进。
