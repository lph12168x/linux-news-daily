AMD Zen 6 上的 FRED 实测：网络与存储 I/O 最高带来数个百分点增益
计算 compute
11 月 24 日（美东周二），Phoronix 用刚上市的 EPYC 9006「Venice」平台量化 FRED（Flexible Return and Event Delivery，灵活返回与事件投递）的性能影响。FRED 是相比传统 IDT 更高效、更现代的中断、异常与系统调用处理机制，全部 Zen 6 处理器均支持，而 Linux 自 7.1 起已默认启用（此前 Intel Panther Lake 上的首测就显示不错收益）。由于现有 EPYC 9006 跑分都开着 FRED，这次在双路 EPYC 9686F、Ubuntu 26.10 + Linux 7.4 Git 内核上强制关闭 FRED 做对比，覆盖 xfr / Ethr（TCP、UDP 延迟与带宽）、ClickHouse（1 亿行数据集）、CockroachDB（KV 读占比 60% / 95%、512 并发）等负载。结论是 I/O 侧（网络与本地存储）最高约数个百分点的增益来自 FRED；它是 EPYC 9006 出色表现的贡献因素之一，与 MRDIMM-12800 支持、SMT 表现及其他架构改进共同作用。
关注理由：FRED 已从「Intel 新特性」变成 Zen 6 的通用能力，且内核默认开启——这意味着服务器 I/O 与数据库负载的基线已经悄悄改变；对做性能优化与跨代对比的人来说，需要把 FRED 开关纳入变量控制。

TornadoVM 8.2 发布：新增 AMD ROCm HIP 后端，Java 代码可直接 JIT 到 Radeon/Instinct
计算 compute
11 月 24 日，面向 GPU 内核编程的 Java 框架 TornadoVM 8.2 发布。基于 OpenJDK 21+ 的 Java 代码可被 JIT 编译到 NVIDIA CUDA、OpenCL C、Apple Metal，如今再增加 专用 ROCm HIP 后端（PR #1327），直接与 HIP 运行时对接，Windows 与 Linux 均可用。此前 TornadoVM 已能通过 OpenCL 路径跑在 AMD Radeon / Instinct 上，新后端意味着更好的性能与可靠性；此外还改进了 Apple Metal 支持、Eclipse OpenJ9 与 IBM Semeru 兼容性等。发布与下载见 GitHub v8.2.0。
关注理由：Java 生态终于有了直连 ROCm 的 GPU 编程路径，不必绕 OpenCL；对 AMD GPU 上做异构计算与可移植内核的团队，这是一条值得评估的新工具链。

Ubuntu 26.10 让 Panther Lake 的 Arc B390 再提速：Linux 7.3 + Mesa 26.2 是关键
图形 GPU
11 月 24 日，Phoronix 在 Dell XPS 14 DA14260（Core Ultra X7 358H、32GB LPDDR5-9600、Arc B390 核显、2880×1800 屏）上对比预装的 Ubuntu 26.04 LTS 与 Ubuntu 26.10。前者为 Linux 7.0 + GNOME Shell 50 + Mesa 26.0.8 + GCC 15.2，后者升级到 Linux 7.3 + GNOME Shell 51 + Mesa 26.2 + GCC 15.3。结果显示 Arc B390（Xe3）图形性能提升最明显，尤其是基于 Vulkan API 的测试；代码编译等任务也有小幅提升，部分 Python 测试有增益（另有 SonicJSON 回退，非 Panther Lake 独有，AMD 平台同样复现），且性能提升并未带来明显 CPU 功耗差异。坚持 LTS 的用户可在 2026 年 2 月的 Ubuntu 26.04.2 中拿到回移植的 HWE 新栈。
关注理由：同一块 Xe3 核显在新内核 + 新 Mesa 下即可获得可观图形增益，说明 Linux 图形栈迭代本身就是「免费性能升级」；对采用 Panther Lake 的设备选型与系统版本策略有直接参考。

Proton 11.0-3 发布：新增一批可玩游戏，更新 DXVK 与 VKD3D-Proton
图形 GPU
11 月 24 日，Valve 发布 Proton 11.0-3（Wine 下游分支，用于 Steam Play 在 Linux 运行 Windows 游戏）。新版本让 Hero Plus、City Car Driving、Bloody Zombies、Blair Witch VR、IL-2 Series、One Shot: Fading Memory 等一批游戏达到「可玩」状态；同时包含大量错误修复、多款游戏的手柄支持改进，并修复若干 Proton 11 回归问题。图形栈方面更新了 DXVK 与 VKD3D-Proton（D3D12-on-Vulkan），另含 Wine Mono 更新、面向 ARM64 的 FEX 2610 等。更新已开始向 Steam 推送，完整变更见 GitHub release。
关注理由：Proton 的每次小版本都直接决定 Linux / Steam Deck 上可玩游戏的数量与稳定性；DXVK、VKD3D-Proton 与 FEX 同步更新，也让 ARM64 掌机与 x86 平台受益于同一图形栈演进。

Canonical 披露 Ubuntu「AI 桌面交互」计划：warty-prototype 统一入口，强调本地推理与可选启用
显示 display
11 月 24 日，Ubuntu 桌面团队成员 Didier Roche 披露 Canonical 的「与桌面交互的新方式」计划，原型 Snap 名为 warty-prototype，目前仍是设计样机。它表面上是类似快速启动器的入口（即时查找文件与启动应用），但目标是「不再把互不相连的 AI 小组件散落在桌面上」，而是提供统一的、键盘与语音友好的入口，把应用、本地上下文与智能辅助连接起来，并且仅在用户明确请求时介入。Canonical 强调该方案严格可选（opt-in）、本地优先（端侧推理）、隐私与安全优先；这是在 Ubuntu 26.10 的 Myna 语音转文字技术预览之后的进一步动作。官方计划 2026 年 1 月分享架构细节与首个版本，并征求社区反馈。
关注理由：这是主流发行版对「AI 如何进入桌面」的一次明确表态：不做常驻悬浮助手，而是走本地推理 + 显式触发的单一入口；对桌面交互设计与隐私边界的走向有风向标意义。
