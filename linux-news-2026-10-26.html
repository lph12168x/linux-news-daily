Linux 7.4 DRM 图形驱动更新：AMDGPU HDMI 2.1 默认启用打头阵
图形 gpu
Linux 7.4 合入全部 DRM 驱动更新。最受关注的是 AMDGPU 的 HDMI 2.1 Fixed Rate Link（FRL）正式默认启用，VRR/FreeSync 与 ALLM 也已就位、不再有回归风险——这项被 HDMI Forum 卡了多年的开源驱动工作在今年初解禁后终于全面落地。数据中心侧 AMDGPU 新增 UALink over Ethernet（UALoE）支持，并支持 Ryzen AI Max 400 系列（Gorgon Halo）的 NPU。Intel Xe 驱动在迁移队列上带来 CPU binds 与 ULLS（应可提升性能），加入 vRAM 健康检查与劣化显存处理，重心持续投向已定名 GPU D 系列的 Crescent Island 加速器。NVIDIA 侧为 Nova 驱动继续涌入大量 Rust 代码，Nouveau 常规修复。高通 MSM DRM 启用 Adreno A830、A845、A850 与 X2-85 GPU 支持，Rockchip DRM 则在推进 HDMI 2.0。
关注理由：HDMI 2.1 默认启用是 AMD 桌面/笔记本用户多年等待的功能落地；MSM 对 Adreno X2 系列的使能直接关系 Snapdragon X2 笔记本 Linux 支持进度，Xe 的 CPU binds/ULLS 与 vRAM 健康检查对 Intel 平台同样是实打实的改进。

Borealis：Asahi 的 Apple Silicon Vulkan 驱动被 fork 出来「Vibe Coding」
图形 gpu
Khronos Vulkan-Docs 收到一个注册 VK_DRIVER_ID_AURORA_BOREALIS（35）的 PR：新驱动 Borealis 由 Aurora Silicon 项目维护，从 Asahi Linux 的 HoneyKrisp Mesa Vulkan 驱动 fork 而来，覆盖 M1 到 M5 及 A18 Pro，但存活于自己的 Mesa fork 而非上游 Mesa（合并前暂时沿用 HoneyKrisp 的 driver ID）。Aurora Silicon 自称目标是从安装到日常使用的完整 Apple Silicon Linux 体验，还在移植 Windows 到 Apple Silicon。项目刚起步，其 Mesa fork 目前的主要动作是删掉 Mesa 的 AI agents 文档/政策、换成允许 AI 贡献的自有政策——该改动由 Claude Opus 5.5 共同署名，整条 fork 带有明显的 vibe coding 冒险色彩。
关注理由：Mesa 社区刚在 10 月放宽 AI Agent 参与规则，随即出现整条 fork + 允许 AI 贡献的组合，是观察「AI 辅助驱动开发」走向的标志性样本；对 Apple Silicon GPU 栈的演进也值得跟踪。

Wayland 新协议 ext-transient-output 提案：为 VNC/远程软件补齐动态输出
显示 display
知名 Wayland 开发者 Simon Ser 发起 ext-transient-output 协议合并请求：允许特权客户端动态创建独立的虚拟输出（wl_output），客户端销毁对象时合成器即移除该输出，且不绑定任何硬件设备。它与已有的 ext-transient-seat（动态创建独立输入 seat）互补——虚拟 seat 配虚拟键盘/指针协议解决远程桌面的输入侧，ext-transient-output 补齐输出侧；虚拟输出再经 ext-image-copy-capture 捕获后送到远程客户端显示。wlroots 合成器库已有实验性 draft MR 实现。
关注理由：远程桌面/VNC 在 Wayland 世界长期缺一块拼图，输入（transient-seat）+ 输出（transient-output）+ 捕获（image-copy-capture）链路齐了之后，Wayland 远程方案将显著完善。

KDE Plasma 6.9：KWin 的 Wayland 画中画支持转正并默认启用
显示 display
Plasma 6.8 发布刚过一周，KDE 开发者已转向 Plasma 6.9 新特性。本周最重要的变化是 KWin 合成器对 Wayland Picture-In-Picture（PiP）协议的支持宣告稳定并在 6.9 默认启用——浏览器等支持 Wayland PiP 的应用从此开箱即用，无需额外配置。其他进展：Plasma Browser Integration 新增 Brave 浏览器支持；即将发布的 Plasma 6.8.2 点版本在修复多显示器设置问题与一批回归。
关注理由：PiP 是高频日常场景，Wayland 协议级支持 + 合成器默认开启意味着多任务视频体验的实质性改善；6.8.2 的多显示器修复也值得等。

Vulkan 1.4.366 发布：swapchain 新增 SMPTE ST 2094-50 HDR 动态元数据
显示 display
Vulkan 1.4.366 收录过去两周的规范修复与澄清，外加一个新扩展：Google 工程师贡献的 VK_GOOGLE_hdr_SMPTE_ST_2094_50_metadata，为 Vulkan swapchain 加入 SMPTE ST 2094-50 动态元数据支持。该标准由 Google、Apple 与 NBC Universal 共同开发、今年 8 月定稿，主打改善 SDR 与 HDR 内容混合播放时的亮度突变与不一致问题。Google 正同步把 ST 2094-50 推进 Chrome 等软件以改善 HDR 视频体验。
关注理由：HDR/SDR 混播的亮度一致性是流媒体与桌面显示的真实痛点，swapchain 层面的标准元数据通道是 Linux 图形栈 HDR 成熟化的又一步。

FFmpeg 9.1 准备发布：APV Vulkan 编码器 + NVIDIA 光流 FRUC 帧率上变换
显示 display
FFmpeg 9.1 进入发布流程。新增 APV（Advanced Professional Video，免版税编码）的 Vulkan 编码器，使 APV 可经 shader 在 GPU 上加速；另一大亮点是 vf_fruc_vulkan 滤镜——NVIDIA Optical Flow 加速的 FRUC（Frame Rate Up-Conversion）插帧。Vulkan 侧还有 H.265 Vulkan 编码优化。其余要点：AAC 编码器大幅改进、H.264 data partitioning、libastcenc ASTC 图像编解码、LCEVC 载荷合并 bsf、D3D12 DirectML 零拷贝 ONNX Runtime 推理后端等。代码已在 release/9.1 分支。
关注理由：APV Vulkan 编码 + NVIDIA 光流插帧把视频转码/帧率上变换进一步推向 GPU 加速，对直播、补帧与云端转码管线都有直接价值。

AOMedia 力推 AV2 早期采用：YouTube 2027 年初上线，Intel 开发 SVT-AV2
显示 display
继 5 月 AV2 v1.0 规范发布后，AOMedia 本周发布新闻稿宣传 AV2 的「生态势头」：压缩效率较 AV1 约提升 30%，并改进 HDR 表现。Google 正在 YouTube 与 Chrome 中试验 AV2，YouTube 的 AV2 流预计 2027 年初上线；Meta 承诺在 Facebook 与 Instagram 视频中采用 AV2。编码器方面，Intel 正开发基于 CPU 的 SVT-AV2，延续其在 SVT-AV1 上的成功路线（此前还有 SVT-HEVC、SVT-VP9）。
关注理由：AV1 之后下一代免版税编解码的产业布局已清晰，YouTube/Meta 的时间表直接牵动浏览器、硬件解码与显示管线的后续演进节奏。

oneDNN 3.14 发布：AMD Zen 优化首次进上游，初始支持 ACE 指令
计算 compute
UXL Foundation 发布 oneDNN 3.14，最值得注意的是 Intel/AMD 本周官宣围绕 PyTorch/oneDNN 协作后，AMD Zen CPU 优化首次进入 oneDNN 上游：改进 MATMUL 与 inner-product 原语在 Zen 处理器上的性能。该优化需 opt-in：以 ONEDNN_X64_USE_ZEN=ON 构建，且目前依赖 ZenDNN 代码位于 oneDNN 树内（可用 ONEDNN_ZENDNN_FETCH=ON 自动拉取）。3.14 还初始支持 AMD/Intel 未来处理器共用的 AI Compute Extensions（ACE）指令，改进 Diamond Rapids 的 AVX10.2 与 AMX 性能；GPU 侧优化了 Intel GPU D 系列（Crescent Island）与 Nova Lake P 的 Xe3P-LPG。
关注理由：AMD 把 ZenDNN 的 Zen 改进推进上游 oneDNN，x86 CPU 推理优化正式收敛一条主线；ACE 双厂商共建的指令集值得持续跟踪。

OpenSSL 4.1 稳定版发布：DTLS 1.3 + 面向 ML-DSA 的 AVX-512 优化
计算 compute
OpenSSL 4.1 稳定版发布。新特性包括：DTLS 1.3 支持（更快握手、前向保密、内建后量子密码支持、优化报头）；GREASE 机制（在 TLS 握手中发送随机无意义值以尽早发现对端对未知值的处理缺陷）；AVX-512 侧新增面向 ML-DSA 后量子签名的 SHAKE x4 优化实现，以及 AES-CBC 解密的 AVX-512 + AES 优化。同时正式退役 Windows Itanium 与 Windows CE 支持。Alpha 阶段的优化实测数据已在 OpenBenchmarking.org 公开。
关注理由：后量子密码（ML-DSA）+ AVX-512 的组合直接关系服务器 TLS/VPN 的未来性能基线，DTLS 1.3 对 QUIC 类工作负载也是关键底层依赖。

Linux 启动期内存分配器提速约 5000 倍：KHO 内存检索 268 秒 → 50 毫秒
内核 kernel
Linux 7.4 的 memblock 拉取请求中，Google 工程师 Tarun Sahu 发现 mm/memblock.c（页面分配器就绪前的早期物理内存分配器）在 memblock_add_range() 与 memblock_isolate_range() 中用线性扫描寻找候选区域，改为二分查找后最坏复杂度降为 O(N log N)（顺序追加为 O(N)）。在 KHO（Kernel Handover，服务于 Live Update Orchestrator 等内核实时交接机制）产生大量不相交 folio 的重碎片场景下，KHO 内存检索时间从约 268 秒降至约 50 毫秒。补丁评论惊讶这段线性搜索竟存活至今。
关注理由：一行数据结构选择的修复带来约 5000 倍提升，是内核「老代码挖宝」的典型案例；KHO/Live Update 是热升级与虚拟机快速重启的基础设施，其性能直接决定可用性。
