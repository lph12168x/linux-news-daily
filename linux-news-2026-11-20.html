AMD AI Engine「AIE」加速器驱动提交主线内核评审：Versal Gen 2 的 VLIW SIMD 阵列
计算 compute
AMD 于周三（11-18）向 dri-devel 邮件列表提交全新的 AMD AI Engine（AIE）加速器驱动，寻求进入主线 Linux 内核。它与内核中已有的 AMDXDNA（面向 Ryzen AI NPU）驱动相互独立，服务对象是用于 Versal 自适应 SoC 的 AI Engine——一片由 二维 VLIW SIMD 向量处理器阵列构成的硬件，面向 DSP、机器学习等场景，单颗 SoC 可集成数十到数百个 AI Engine。去年 AMD 曾提交过较基础的版本，此次重写后只针对更新的 Versal Gen 2 SoC；驱动遵循内核标准的 accel 加速器框架，而非继续维护下游 out-of-tree 版本。补丁由 AMD 的 Gregory Williams 发出，目前处于 upstream review 阶段。
关注理由：这是 AMD 把 FPGA 自适应计算平台上的 AI Engine 纳入标准内核加速器框架的关键一步：对做异构计算、加速器驱动与用户态调度的人来说，统一的 accel 接口意味着更少私有补丁、更容易与主线内核的功耗/内存管理协同。

Mesa 26.3.1 发布：Intel「Jay」着色器编译器与 RADV 集中修复
图形 GPU
季度特性版 Mesa 26.3 的首个维护版本 26.3.1 已发布，适合希望等 x.1 再升级的发行版与用户。本次更新包含对全新 Intel「Jay」着色器编译器的一批零散 bug 修复，以及 Windows 平台 D3D12 Dozen（Dzn）驱动的改动；RADV 仍然改动最多——包括暂停条件渲染（conditional rendering）的处理、Valve 的 Samuel Pitoiset 继续做 memcpy 优化、修复 RDNA2 上的 VRS 等。Zink 现在把条件渲染的使用收拢到 VK_EXT_conditional_rendering 扩展之后，以规避某个未点名的专有驱动不支持该扩展导致的错误。完整补丁列表见 mesa-dev 邮件列表公告。
关注理由：Intel Jay 是新编译器的首个维护窗口，RADV 的性能与 RDNA2 修复又直接惠及 AMD 游戏与计算用户；Zink 对扩展能力的显式门控也体现了 Mesa 面对专有驱动兼容问题时的一贯工程取向。

Ryzen AI Max+ 395 双系统实测：Ubuntu 26.10 综合领先 Windows 11 Pro 约 1.16 倍
计算 compute
Phoronix 在搭载 AMD Ryzen AI Max+ 395（Strix Halo）的 GMKtec EVO-X2 迷你主机上，对出厂 Windows 11 Pro 与 Ubuntu 26.10 做了超过 100 项基准测试。按几何平均计算，Ubuntu 26.10 的整体性能是 Windows 11 Pro 的 1.16 倍。细分来看：Blender 5.3 的 CPU 渲染 Linux 明显更快，V-RAY 也偏向 Ubuntu，但 ROCm HIP 路径下 Windows 11 Pro 通常略胜一筹；llama.cpp 的纯 CPU 推理 Ubuntu 占压倒性优势，改用 Radeon 8060S 核显 + Vulkan 后端后差距显著缩小，但 Ubuntu 通常仍为最优。测试还覆盖 GPU/图形与功耗表现。
关注理由：Strix Halo 是「大核显 + 统一内存」本地 AI 的代表平台：同一硬件上 Linux 在 CPU 侧与 Vulkan 推理领先、ROCm HIP 反而 Windows 略优的分化，对选择部署系统与优化后端很有参考价值。

Unsloth Desktop 接入 Ryzen AI NPU：XDNA 2 及更新型号，Linux 同样可用
计算 compute
AMD 与 Unsloth 宣布，Unsloth Desktop 现已支持调用 AMD Ryzen AI NPU 做本地推理，首批覆盖 XDNA 2 及更新架构的笔记本与台式机处理器。官方称已有超过 100 个 agentic AI 应用与工作流可在该组合下运行；模型服务与推理基于 AMD 开源的 Lemonade 与 FastFlowLM 项目实现。AMD 特别向 Phoronix 确认：这项 NPU 支持并不限于 Windows，Linux 版本同样可用。相关细节见 AMD 官方博客。
关注理由：与 ROCm 扩展 GPU 侧覆盖面相呼应，Unsloth 把 mainstream Ryzen AI NPU 纳入常用本地推理桌面工具，且明确支持 Linux——对端侧 agent 工作流的 NPU 卸载落地是实质性利好。

LLVM 历时近十年的重新授权基本完成：99.5% 以上代码转为 Apache-2.0 with LLVM exception
内核 kernel
Kristof Beyls 宣布 LLVM 自 2017 年启动的代码重新授权工作基本收尾：历史上贡献过的代码中，超过 99.5% 已纳入 Apache-2.0 WITH LLVM-exception 许可，余下部分或已移出代码库、或体量过小不构成版权问题。1,300 多名个人贡献者与约 100 家组织同意为历史贡献重新授权；自 2019 年 1 月 19 日起的新贡献已统一采用该许可，而此前的代码使用 UIUC/NCSA（部分运行时库为 MIT）许可，因此追溯联系作者耗时近十年。LLVM 25（2027 年）将随附更新后的 LICENSE 文件与文档，统一指向新许可。
关注理由：LLVM 是 Mesa RadeonSI/RADV/AMDGPU 后端与大量内核/编译器工具链的共同底座；许可统一降低了下游发行版与商业产品集成的法律摩擦，也让后续代码贡献与合规审查简单得多。
