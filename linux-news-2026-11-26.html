Khronos 正式转向 KosmicKrisp：Mesa 的 Apple 平台 Vulkan 1.4 实现取代 MoltenVK
图形 GPU
11 月 25 日，Khronos Group 宣布 Vulkan Portability Initiative 及其 MoltenVK 层已「完成使命」并进入弃用状态；由 LunarG 主导、已内建在 Mesa 中的 KosmicKrisp 成为 Apple 平台上 Vulkan 的首选方案。 KosmicKrisp 基于 Apple Metal 之上的分层实现，已在 Apple Silicon 上通过 Vulkan 1.4 一致性认证，因此为可移植性而设的临时 Vulkan 扩展也不再必要——它是目前唯一提供完整一致性实现的分层方案。MoltenVK 仍可继续运行既有应用，也仍是旧款 Intel Mac 与旧版 macOS 的选择；KosmicKrisp 当前仅支持 macOS，不支持 iOS，也无意向支持 Intel Mac。
关注理由：这是 Apple 平台图形栈的一次正式换代：从「可移植性扩展」转向真正的一致性 Vulkan 1.4，意味着 macOS 上的 Vulkan 应用行为更接近其他平台；跨平台图形/推理框架的后端选型需要重新评估。

Linux 7.5 为 Intel Xeon 服务器加入 P2PDMA 白名单：Skylake-SP 到 Diamond Rapids 全覆盖
内核 kernel
11 月 25 日，一个已进入 PCI 子系统 next 分支、将在 Linux 7.5 合入的补丁，把 Skylake-SP 一直到下一代 Diamond Rapids 的 Intel Xeon 服务器 CPU 显式加入 cpu_supports_p2pdma() 白名单。此前 AMD Zen 及更新平台已被覆盖。Intel 工程师 Pavel Popov 指出：P2PDMA 要求设备共享上游桥或主机桥命中 pci_p2pdma_whitelist[]，但 VMware 客户机中直通设备直接挂在虚拟根总线上，Hyper-V 客户机中每台设备独占 PCI 域，导致哪怕宿主支持也无法通过检查——受影响的是 GPU、NIC 与 NVMe 等独立 PCIe 设备。补丁已在 VMware ESXi 9.0 上的 Linux 客户机中，用 Intel Level Zero P2P 基准（ze_peer）+ Arc Pro B60 完成验证。Linux 7.5 合并窗口约在 12 月底开启，2027 年 Q1 正式发布。
关注理由：P2PDMA 让 PCIe 设备之间直接搬数据、绕开主机内存，是 GPU 直连存储/网卡与零拷贝管线的基础。虚拟化场景下长期失效的检查被修正，对 RDMA、GPU Direct 类方案和云上加速器部署有直接价值。

PostgreSQL 19 在 6 代 EPYC「Venice」上全面超越 18，只读负载提升尤为显著
计算 compute
11 月 25 日，Phoronix 发布 PostgreSQL 19 与 18 的首轮对比测试：平台为 单路 AMD EPYC 9996「Venice」（256 核 Zen 6C）、16 通道 MRDIMM-12800、PCIe Gen6 NVMe（Micron 9650 PRO 7.6TB），两次运行除数据库版本外配置完全一致。PostgreSQL 19 带来异步 I/O worker 自动扩展、面向现代 CPU 的更多 SIMD 加速、更快的外键检查、并行 autovacuum 等优化，同时因性能不稳定而默认关闭 JIT。结论是全面领先（clean sweep）：只读负载提升最明显，吞吐更高、延迟更低；读写混合负载在不同数据规模与客户端数下也有可测量增益。
关注理由：数据库是典型的企业级计算负载。在顶级 Zen 6 平台上零调参即可获得全面性能提升，说明 PG 19 的 I/O 与 SIMD 优化已经落地；值得作为数据库选型与内核/内存平台升级的基线数据。

Linux 7.4 停用 LLVM Profi：AutoFDO 下出现性能退化与病态编译时间
内核 kernel
11 月 25 日，本周合入 Linux 7.4 的 Kbuild 修复补丁禁用 LLVM 的 Profi（flow-based profile inference）算法在内核 AutoFDO 构建中的使用，并将回移植到稳定分支。Profi 是 Clang 21 起在传入 -fprofile-sample-use 时默认启用的 PGO 采样推断算法，但它与 Linux 内核 AutoFDO 使用的 flow-sensitive discriminator 存在已知冲突：可能导致最终二进制变慢，并在某些内核控制流图上出现病态编译时间（30 分钟以上甚至挂起）。补丁说明直言其目标是避免「运行时性能下降和病态编译时间」，但并未给出量化数字。
关注理由：对用 Clang 21+ 加 AutoFDO 调优内核的团队，这是一条必须知道的构建变更：PGO 不再是「开了就一定更快」，编译器新特性与内核采样机制的不匹配会直接反噬性能与构建效率。

Rust 浏览器引擎 Servo 0.8：HTML5 视频字幕、Flutter Web 与 WebGPU 读写提速
显示 display
11 月 25 日，Servo 项目披露 Servo 0.8 的 10 月进展。这个 Rust 编写的浏览器引擎与 Servoshell 演示浏览器新增了 HTML5 video 元素的字幕与封闭字幕（captions）支持；修复 typed array 实现的性能问题后，Flutter Web 内容已能正常工作。此外还支持 text-decoration-line 的拼写/语法错误值、CSS progress() 数学函数与 image 输入类型，并让复杂页面缩放更平滑、降低内存分配与占用、修复内存泄漏。渲染方面继续完善 WebGL2 支持、加快 WebGPU 缓冲区读写、加入 Geolocation API，同时增强 embedding API，目标是成为 Chromium CEF 的可行替代。
关注理由：Servo 正从实验性引擎向可嵌入的渲染后端演进；字幕、Flutter Web 与 WebGPU/WebGL2 的补齐，加上对标 CEF 的定位，让它成为桌面应用内嵌渲染的一个值得跟踪的新选项。
