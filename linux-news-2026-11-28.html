Wine 11.23 发布：首次支持 ARM64 macOS，32 位模拟加入 AVX
图形 GPU
11 月 27 日，Wine 11.23 作为双周开发版发布，距离 12.0 候选阶段又近一步。最引人注目的是首次加入 ARM64 macOS 支持：为 Apple Silicon Mac 构建 Wine 需要调整构建流程并对 NTDLL 做相应修改，且该支持依赖 macOS 27。ARM64 侧的另一项进展是，在 64 位 ARM 上的 32 位模拟中启用 AVX（高级向量扩展）——上一版 11.22 只支持 x86_64 的 AVX 模拟，如今延伸至 32 位程序。图形栈方面，本版集成 VKD3D 2.2（D3D12 over Vulkan 的多项改进），并合入了远程 OpenGL swapchain 图像呈现支持，使 CEF（Chromium Embedded Framework）在 Wayland 下的 Wine 中正常工作；WIDL 的 C++ 头文件生成也得到改进，另有约 40 项已知错误修复。
关注理由：Wine 正同时推进两条重要路线：ARM64 上的向量指令模拟扩大可运行软件范围，跨进程 OpenGL 呈现则打通了 CEF 在原生 Wayland 桌面的图形链路。对兼容层、游戏与桌面应用迁移而言，这两项都是基础设施级进展。

高通 Earthqaic Gallium3D 驱动合入 Mesa 27.0：面向 Cloud AI 加速器
计算 compute
11 月 27 日，一个全新的 Gallium3D 驱动 Earthqaic 被合入 Mesa Git，将随 Mesa 27.0（预计 2027 年 Q1）发布。它由高通开发，目标硬件是 Cloud AI 加速器「QAIC」，并不面向常规图形场景，而是专门服务 Gallium3D 的 Teflon AI 加速框架与 Rusticl（Rust 实现的 OpenCL 驱动）。开发者特别强调当前代码非常实验性、功能原始：只实现了张量加法与卷积，能编译并执行一个简单的 OpenCL「hello world」内核，且可能存在稳定性问题。该项目与数年前已进入 Linux 主线的 QAIC 内核驱动形成配套。
关注理由：这是 Mesa 开放栈向 AI 加速器延伸的又一步：GPU 驱动框架被复用于 NPU 类设备，让 Teflon / Rusticl 有机会以统一接口访问 QAIC。虽然仍是概念验证，但值得关注后续算子覆盖与稳定性演进。

Intel ANV Vulkan 驱动默认启用高效 64 位寻址模式 e64
图形 GPU
11 月 27 日消息，Mesa 27.0-devel 中 Intel 的 ANV Vulkan 驱动已默认启用高效 64 位寻址模式「e64」。e64 随即将推出的 Nova Lake P 处理器 Xe3P 核显登场，为着色器提供原生 64 位显存寻址，取代此前 Intel GPU 着色器一直使用的 32 位偏移模式。Nova Lake P 同时支持 e64 与旧 32 位模式，而此后的 Intel 显卡预计将完全去掉 32 位偏移模式。本次由 Mesa MR !46751 带入 ANV 的 e64 路径错误修复，并称开启 e64 后的测试通过率高于关闭时，因此具备默认开启条件；内核与 Mesa 支持有望在硬件正式上市前就绪。
关注理由：寻址模式看似底层，却直接影响显存寻址能力与着色器编译路径：e64 是 Intel 未来 GPU 的事实标准，默认开启意味着驱动栈已开始为新硬件的真实工作负载做准备。

Intel Compute Runtime 26.44.40734.8：OpenCL 3.1 短暂上线后回滚，性能继续优化
计算 compute
11 月 26 日，Intel 发布开源 GPU 计算栈 Compute Runtime 26.44.40734.8（Linux / Windows 共用）。本版原本包含一项在所有受支持 Intel 显卡代际上启用 OpenCL 3.1 的补丁，但在最终版本中被回滚，对外暴露的仍为 OpenCL 3.0，回滚补丁并未说明具体原因。性能方面，针对 Intel GPU D 系列「Crescent Island」做了拆分 upstream writes 等优化，并对 Level Zero 做了通用代码重构以优化编译；当缓冲区由主机内存支撑时，Level Zero 图像会采用在 CPU 上复制主机指针的 staging copy。构建于 Level Zero API 之上的 OpenCL LEO 代码也在持续完善，为其在 Nova Lake 上默认启用做准备；另新增 Panther Lake 设备 ID 0xB0A1，并附带大量错误修复（本版合计 400+ 补丁）。
关注理由：Compute Runtime 是 Intel GPU 上 GPGPU / AI 推理的关键软件层：Crescent Island 的吞吐优化与 Level Zero 重构指向未来硬件，而 OpenCL 3.1 的回滚提醒开发者在依赖新版 API 特性时要以实际暴露版本为准。

GMKtec EVO-X2 评测：Strix Halo 迷你主机的 Linux 能效表现
计算 compute
11 月 27 日，Phoronix 发布 GMKtec EVO-X2 评测。该机采用 Ryzen AI Max+ 395「Strix Halo」，可选 64GB / 128GB LPDDR5X 与 1TB / 2TB NVMe（双 M.2 2280 槽），接口含 USB4、HDMI 2.1、DisplayPort 1.4 与 2.5G 网口，Wi-Fi 为 MT7925。测试对比了 Ryzen AI Halo、Framework Desktop、BOSGAME VTA-439（Ryzen AI 9 HX 470）与 Dell Pro Max GB10（NVIDIA GB10），多数机型运行干净的 Ubuntu 26.10。结果上，EVO-X2 的原始性能略低于两款高端 Strix Halo 机型，但能效往往持平或更优：平均功耗约 80W、峰值 132W，而 Framework Desktop 与 Ryzen AI Halo 约 105W 平均 / 180W 峰值；核心与 GPU 温度也最低，无散热问题。按下机身侧面的物理风扇模式键后，与其他 Strix Halo 机型的性能差距会进一步缩小。Linux 侧在 Ubuntu 26.04 / 26.10、Fedora 45、CachyOS 上均无兼容性问题。起售价约 2199 美元（64GB + 1TB）。
关注理由：Strix Halo 正在从整机走向多样化形态：这款迷你主机用更低功耗换接近的算力，且 Linux 开箱可用，适合关注本地大模型推理与紧凑型计算节点的团队。风扇模式未接入系统平台配置文件的取舍也值得硬件厂商借鉴。
