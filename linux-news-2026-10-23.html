RADV 为 GFX8 默认启用 Vulkan FP16：让更多新游戏在 Polaris 等老卡上跑通 Steam Play
图形 gpu
Valve 工程师 Georg Lehmann 向 Mesa 合入一行补丁（Mesa 27.0，并将回移当前稳定系列）：RADV 在 GFX8 硬件上默认暴露 Vulkan FP16 支持，场景限定为 VKD3D-Proton（D3D12）。
背景：GCN 3/4 代（Tonga 到 Polaris RX 400/500）的 RADV 虽早有 radv_enable_float16_gfx8 选项，但一直默认关闭——这些老卡上 FP16 通常没有性能收益、有时反而更慢。而新发布的 Windows 游戏开始把 FP16 当作必需项，不开就出问题：该补丁直接修复了《巫师 3》近期更新后的 SSAO 异常。
对原生 Vulkan 应用仍不默认暴露，避免老卡为用不上的 FP16 付出代价。
关注理由：这是「老硬件长尾维护」的典型样本：一行改动决定一批 RX 580 级别设备能否继续跑新游戏，Steam Deck 之外的低端 Steam Play 硬件（Steam Survey 里 Polaris 仍有可观份额）直接受益。补丁的取舍也值得借鉴——按调用方（D3D12/VKD3D-Proton）而非全局限定暴露扩展，兼顾兼容性与性能，与 10-20 期「Intel 为 Proton 推进 XMX 加速 XeSS」同属 Proton 兼容性补链。

Linux 7.4 Workqueue 优化：大机器上空闲 flush 快 10~100 倍
内核 kernel
Tejun Heo 的 workqueue PR 合入 Linux 7.4，带来一个少见量级的优化：flush workqueue 时只遍历自上次 flush 以来实际用过的队列，而非每个可能 CPU 各一遍。
数据（来自提交说明）：192 核 2 路机器上，空闲 per-cpu workqueue 的 flush 吞吐从 4 万/秒提升到 420 万/秒，空闲 unbound 从 45 万/秒到 430 万/秒；16 线程排队+flush 混合负载也有 3 倍左右提升。动机来自华为工程师 Yao Kai 的报告：128 核机器上 XFS CIL workqueue 每次日志强制的 flush 在遍历上要花最多 64μs。
XFS 每次日志强制都会触发该路径，文件系统重负载下这是高频热路径；全部队列都活跃时的密集 flush 在 per-cpu 类型上不变、unbound 略慢 15~20%。
关注理由：「10 到 100 倍」级别的内核基础层优化极其罕见，而且改的是所有大核数服务器都吃到的公共路径——XFS/文件系统日志、异步工作队列场景直接受益。亮点还有一点：这是一个非 AI 参与的经典人类手艺活（报道特别点名），在当下内核圈 AI 补丁洪流的语境里反成卖点。对关注服务器性能与文件系统的同学，7.4 的 workqueue PR 值得细读。

Modular MAX 源码全面开放：图编译器与推理运行时公开，附新 MAX 许可证
计算 compute
继 8 月 Mojo 语言开源（Qualcomm 收购 Chris Lattner 的 Modular 之后）后，Modular 宣布 MAX 全部源码开放：MAX 图编译器、MAX 运行时、设备扩展钩子全部公开，随 MAX 26.7 版本发布。
许可是新的「source available」MAX License：允许免费构建和分发商业产品、无版税；但限制 AI 辅助重实现 MAX、基于 MAX 的商业托管推理服务、以及修改版源码的发布分发（官方称旨在防止碎片化为不兼容版本）。MAX 本体是兼容 OpenAI 端点的高性能 LLM 推理服务器。
关注理由：AI 推理栈又多一个开放的选择：MAX 以图编译器 + 多设备扩展为核心卖点，「设备扩展钩子」开源意味着第三方硬件（NPU/国产加速器等）可以对接 MAX 后端，与 IREE/Torx（10-14 期）这类 MLIR 系编译器的生态竞合值得跟踪。
许可证条款同样有信息量：明确禁止「AI 辅助重实现」和商业托管转售，是 source-available 许可针对 AI 时代新玩法的第一批探索，后续同类项目大概率跟进参考。

Linux 7.4 调度器更新：短时间片任务延迟最高降 55%，NVIDIA Vera 偏好 SMT
计算 compute
Linux 7.4 的调度器 PR 合入，几项要点：
① EEVDF 调度器继续优化（Linaro 的 Vincent Guittot）：短时间片任务的调度延迟实测最高降低 55%，延续其在 7.3 里的同方向工作；
② 新合入面向虚拟机的 steal governor：按 steal time 动态管理 vCPU，降低 vCPU 被抢占的代价；
③ NVIDIA Vera（Olympus 核心）偏好 SMT 兄弟线程调度，官方数据该优化带 3~6% 性能收益；
④ 同等浅深的空闲核心改为随机挑选，利于高核数服务器/工作站负载摊匀；另含一处避免发布部分 LLC 利用率数据的 cache-aware 调度修复。
关注理由：调度器是「计算」方向的隐性基础设施：短任务延迟 55% 的改善对交互式负载与微服务 P99 都有意义；steal governor 让 Linux 客户机对「被宿主机偷走的时间」有了主动应对，云上虚拟化场景值得跟进；Vera 偏好 SMT 则与 10-13 期 Vera SMT 实测（+20%、功耗仅 +5%）互相印证——NVIDIA 进军服务器 CPU 后，内核侧的协同调优正在快速跟进。

AMD HIPRT 3.2 发布：支持 Medusa APU（Zen 6 客户端），SRT 剪切与 CUDA 13 兼容
图形 gpu
AMD 发布 HIPRT 3.2——HIP 光线追踪库（Blender 等跨平台软件使用）今年的首个更新：
① 支持即将到来的 AMD Medusa APU（Zen 6 客户端 CPU/APU 家族），图形 IP 覆盖 GFX1170 / GFX1171 / GFX115E；
② 性能优化如变换函数展开（unrolling transform functions）；
③ SRT 帧支持剪切（shear）变换；CUDA 13 兼容性增强；一批缺陷修复与代码库现代化改造。
关注理由：两条线索值得记录：其一，Medusa 的图形 IP 型号首次在这类 SDK 层面得到公开确认（GFX1171 之前已在 Mesa 点版本中出现过「RDNA 4m」workaround，GFX115E 是新面孔），Zen 6 APU 的图形代际轮廓渐清晰；其二，HIPRT 作为 Blender GPU 渲染的 AMD 光追路径，其更新节奏直接影响 Linux 上 Blender 渲染性能的跟进速度。

Snapdragon X2 Linux 初步实测：超出预期，Adreno 开源驱动栈直接可用
计算 compute
Phoronix 发布骁龙 X2 Elite Extreme（X2E96100，18 核，单核 5.0GHz）在 Linux 上的首批基准测试：华硕 Zenbook A16 上运行 Ubuntu 26.10 X1E Concept ISO（内核 7.3）。
关键状态：Adreno 图形的开源 Qualcomm 驱动栈（Freedreno/Turnip）直接可用——对比之下 X1 Elite 在同一镜像上图形还有问题、回退 LLVMpipe。WiFi/音频/摄像头尚未开箱支持，无功耗监控。
对比对象包括 Core Ultra 9 285H、Core Ultra X9 388H（Panther Lake）、Ryzen AI 9 365/HX 370 与上代 X1 Elite，结论是 X2 表现超出预期（为 10 页长评测，细节待后续补测功耗与更多场景）。
关注理由：继 09-24 期「高通提交 Adreno 850 Hawi 补丁」、09-30 期「Ubuntu 26.10 Snapdragon Concept 镜像首度支持 X2」之后，这是 X2 在 Linux 上第一份带数据的横评：图形栈从「补丁评审中」到「实机可跑」的落地速度可观。对关注 ARM 笔电 Linux 生态的同学，X2 与 Panther Lake/Strix Point 的正面对比是 2027 年笔记本选型的重要参照，功耗数据（本轮缺失）是下一波补测重点。

Linux 7.4 crypto 库合入 x86/RISC-V 优化 AES 实现：ECB/CBC/CTR/XTS 等六大模式加速
计算 compute
Google 的内核加密专家 Eric Biggers 持续推进 crypto 库整合：Linux 7.4 合入把 x86/x86_64 与 RISC-V 上六大 AES 模式（ECB、CBC、CBC-CTS、CTR、XCTR、XTS）的优化实现迁入 lib/crypto。
x86_64 上走 AVX 优化代码 + AES-NI 指令；迁移后库 API 与 crypto_skcipher 用法都能吃到加速，同时删掉大量冗余 glue 代码与重复实现。
同批还有 Stian Halseth 为 SPARC64 写的优化 AES-XTS 实现（使用 SPARC 加密操作码）。
关注理由：磁盘加密（dm-crypt/XTS）、VPN（IPsec/CTR）等安全路径的吞吐都压在 AES 实现上，「优化实现进公共库」意味着这些路径自动受益且减少分叉维护成本。这与 7.4 里已合入的 AVX-512 xor_gen()（09-16 期）同属 Biggers 的 crypto lib 收敛工程，内核加密子系统的「架构优化实现下沉公共层」趋势值得持续跟踪。
