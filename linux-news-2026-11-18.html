Valve 新 AMDGPU 补丁直指 Steam Play 游戏卡顿：引入 VM update context 与 AMDGPU_GEM_VA2 ioctl
图形 GPU
Valve Linux 图形驱动团队的 Natalie Vock 发出新版 AMDGPU 内核补丁系列，目标是显著减少一部分 Windows 游戏经 Steam Play（Proton）在 Linux 上运行时出现的卡顿。问题根源：现代游戏大量使用稀疏绑定（PRT / sparse binding），并依赖 gfx/compute 队列的帧工作与 SDMA 上的稀疏绑定工作重叠；现有实现把 PRT 映射与每次提交同步，密集稀疏绑定会让 gfx/compute 提交长时间停顿，产生肉眼可见的 stutter/hitch；同时每次稀疏绑定更新都要单独一次 ioctl，CPU 在用户态/内核态之间频繁切换。补丁引入 VM update context 结构在不同 VM 更新函数间携带状态（已释放的映射、待处理映射集合），先逐项校验、再原子化一次性应用；配合新的 AMDGPU_GEM_VA2 ioctl 批量更新映射，实现显式同步。补丁未给出具体帧时间数字，目标进入 Linux 7.5 尚待评审。
关注理由：性能瓶颈落在驱动 VM 更新路径而非 GPU 算力本身：稀疏纹理+显式同步是现代游戏引擎常态，这批补丁关系到 AMD 显卡在 Proton 下的实际体验，也可能成为其他驱动处理批量映射的参考设计。

AMD RDNA 4m（GFX117x）量产固件就绪：Zen 6 Medusa Point 核显图形栈拼图补齐
图形 GPU
AMD 向 linux-firmware 合入新提交，更新 GFX1170 / GFX1171 固件，标志 RDNA 4m「GFX117x」核显的生产固件准备就绪。RDNA 4m 是介于 RDNA 3.5（GFX11.5）与 RDNA 4（GFX12）之间的新一代 iGPU 架构，ISA 上有别于 RDNA 3.5，并非简单更名；此前 HIPRT 3.2 已暗示 GFX117x 对应 Zen 6 架构的 Ryzen AI 500 系列（Medusa Point），本次固件合并再次印证 2027 年初的上市节奏。此前 AMDGPU 内核驱动与 Mesa 的 RadeonSI / RADV 已加入 GFX117x 支持，8 月发布过初版固件；本次除兼容性链接外，还新增 VPE 2.0、VCN 5.3、PSP 15.0 TA、GCC 1.7.1 RLC/PFP、SDMA 6.1.4 等 IP 块固件（预训练部件固件名改用「_p」后缀）。配合 Linux 7.4+ 与 Mesa 26.3+，RDNA 4m 的图形栈已基本就位。
关注理由：内核驱动 → Mesa → 固件三层齐备意味着 Zen 6 APU 核显在 Linux 首日可用度大概率不重演「硬件先发、驱动后补」的老问题；VPE 2.0/VCN 5.3 的到位也关系到视频编解码与 AI 多媒体管线。

NVIDIA 工程师提议用户态可控「首选 CPU 核」sysfs 接口：AI 推理 VM 可获更优核分配
计算 compute
NVIDIA 的 Yury Norov 发出 RFC 补丁系列，提出让 Linux 通过 sysfs 暴露可写的首选 CPU 核（preferred cpumask）接口，使用户态可以表达对特定核心的偏好。背景是 Linux 7.4 合入的 steal governor 已引入 preferred CPU mask，用于 VM 中 vCPU 争抢时减少需求；新接口将其扩展到用户态：/sys/devices/system/cpu/cpu[0-9]*/preferred 供逐核设置，/sys/devices/system/cpu/preferred 查看当前活跃的首选核列表。典型场景一是与 Thermald 联动，在核心过热时引导任务迁移或闲置；场景二是同一服务器上同时跑 AI 训练与推理 VM，延迟敏感的推理 VM 可占用更多首选 vCPU，把最终决策交给更了解业务角色的用户态（内核 steal governor 适合同构协作型 VM，非对称负载需要更多信息）。补丁正在 LKML 评审。
关注理由：AI 训练/推理混部与 vCPU 超卖是计算集群的常见痛点：把「哪些核更优先」的控制权从内核启发式交给编排层/守护进程，是调度接口设计上的重要转向，值得关注评审结果及与 cpuset 的交互。

Xfce 4.22 路线图更新：12 月 15 日 pre1 特性冻结，2027 年一季度正式发布
显示 display
Xfce 项目本周更新 Wiki 上的 4.22 路线图：12 月 15 日发布 4.22pre1，同时进入特性冻结与字符串冻结；一个月后的 1 月 15 日发布 pre2 并代码冻结；pre3 与最终冻结日期待定，按惯例正式版通常在数周内跟进，因此 Xfce 4.22 稳定版大概率在 2027 年第一季度落地（距 4.20 发布已近两年）。本期重点是持续推进的 Wayland 支持，以及面板/核心组件改进、更好的 HiDPI 处理等；Wayland 部分仍按单独的 roadmap 页面推进，尚未到完整替代 X11 的阶段。
关注理由：Xfce 是 X11 时代的重要轻量桌面，其 Wayland 迁移进度与 HiDPI 改善直接影响老设备/低配机器的 Linux 显示体验；2027 Q1 的时间点也方便发行版规划下一个开发周期。

REAPER 数字音频工作站获原生 Wayland 移植：WireGuard 作者 Jason Donenfeld 操刀
显示 display
过去十年仅支持 X11 的 Linux 版 REAPER 数字音频工作站，现已提交原生 Wayland 支持的合并请求。移植由 Jason Donenfeld（WireGuard 作者）完成，主要工作围绕 REAPER 底层使用的 WDL C++ 库展开；新实现保留加载 REAPER 既有 X11 插件的能力，用户不必一次性替换插件生态。代码目前在 github.com/justinfrankel/WDL 的 PR #40 上等待合并，更多细节见 Cockos 官方论坛讨论帖。
关注理由：专业音频工具是 Wayland 迁移中公认的硬骨头（低延迟、插件 ABI、窗口管理特殊需求）：REAPER 采用「原生 Wayland + 兼容 X11 插件」的渐进路线，对同类应用有示范意义。
