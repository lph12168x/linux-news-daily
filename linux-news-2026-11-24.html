Mesa NVK 开源 NVIDIA 驱动迈出光追关键一步：合入 TTU 指令支持
图形 GPU
11 月 23 日（美东周日），Mesa 27.0-devel 合入 NVK 开源 NVIDIA Vulkan 驱动的初始 TTU（Tree Traversal Unit，树遍历单元）指令支持，同时补齐 NAK 着色器编译器中的相关处理与 NIR 中间表示的 intrinsic。TTU 指令是 NVIDIA GPU 上控制 RT Core 的指令，本次合并（MR !45929）的直接目标是让 NVK 最终支持 VK_KHR_ray_query 与 VK_KHR_ray_tracing_pipeline 两个 Vulkan 光追扩展。Phoronix 评论称，这是开源 NVIDIA Vulkan 驱动光追能力的又一步，但整个工作「能否在 2027 年全部完成」仍有待观察。
关注理由：NVK 是 Linux 上唯一可完全开源的 NVIDIA Vulkan 实现，光追扩展从「无」到「有」的第一步落在编译器与指令层；对关注开源驱动栈成熟度和 Vulkan 光追生态的人来说，这是需要长期跟踪的里程碑。

Mesa 27.0 的 RadeonSI 默认关闭旧 Radeon 内核驱动支持，GCN 1.0/1.1 用户需升级
图形 GPU
AMD 驱动工程师 Pierre-Eric Pelloux-Prayer 的补丁于 11 月 23 日合入 Mesa 27.0-devel（MR !46489）：RadeonSI Gallium3D 默认关闭对旧 Radeon 内核驱动的兼容支持，目的是推动用户转向 AMDGPU 内核驱动或升级内核。受影响的是早期 GCN 1.0 / 1.1（Radeon HD 7000 系列初期）显卡——约一年前 AMDGPU 在这些 GPU 上达到功能对齐后，内核已默认改用 AMDGPU。若用户仍坚持「新 Mesa + 很旧的内核」，可用环境变量 AMD_DEBUG=use_radeon 临时恢复；但 Mesa 27.1 或更晚版本可能直接移除这部分支持。GCN 1.2 及更新显卡（已用 AMDGPU）与 pre-GCN 老卡（走 Radeon 内核 + R600 驱动）均不受影响；官方建议 GCN 1.0/1.1 用户升级到 Linux 7.1+ 以使用默认的 AMDGPU 驱动。
关注理由：这是 AMD 清理用户态遗留驱动路径的明确信号：老 GCN 卡仍能跑，但支持窗口已进入倒计时。对维护老设备或发行版后端的人来说，需要尽早规划内核与 Mesa 的配套升级。

EPYC Zen 6 对比十年前的 Zen 1：100+ 项测试几何均值 12.1 倍，AI 最高 133 倍
计算 compute
11 月 23 日，Phoronix 发布跨度近十年的服务器性能对比：2017 年的 EPYC 7601（Naples，32 核 Zen 1 / 64 线程、2.2GHz、64MB L3、DDR4-2666 八通道、180W）对阵新上市的 EPYC 9996（Venice，256 核 Zen 6C / 512 线程、1GB L3、16 通道 MRDIMM-12800、96 条 PCIe 6.0、600W）与高频款 EPYC 9686F（96 核 Zen 5 / 5.3GHz、384MB L3）。在相同软件栈（Ubuntu 26.10、Linux 7.3、GCC 15.3）上运行 100 多项测试：双路 9996 相比双路 7601 的几何平均性能为 12.1 倍，双路 9686F 为 8.7 倍。分项来看，OpenVINO 的 AI 负载最高达 133 倍，AVX-512 负载几何均值 16.4 倍，Blender 等创作负载 13.6 倍，HPC 负载 15.6 倍，OpenSSL / 数据库等传统服务器负载最高约 22 倍；即便新平台 TDP 更高，每瓦性能仍约为 5 倍。
关注理由：这组数据把「十年架构演进」量化成了可直接引用的数字：AI 与 AVX-512 的增益远超核心数增长，说明指令集与加速单元才是计算性能跃迁的主因；对选型与容量规划都有参考价值。

VKD3D 2.2 发布：D3D12-on-Vulkan 支持到 Shader Model 6.2，为 Wine 12.0 铺路
图形 GPU
11 月 23 日，VKD3D 2.2 发布，这是在 Vulkan 上实现微软 Direct3D 12 接口、让 Windows 游戏在 Wine 下运行的关键组件。新版本把着色器模型支持提升到 Shader Model 6.2，加入对 Vulkan shader float controls 扩展的利用，并带来多项 HLSL 着色器处理改进、VKD3D 编译器增强与各类修复。按计划，Wine 12.0 的候选版本将在 12 月开始，稳定版定于 2027 年初；VKD3D 2.2 届时会并入 Wine 代码库。可从 WineHQ 的 GitLab release 页面下载。
关注理由：D3D12 是当前 Windows 游戏的主流 API，VKD3D 的着色器模型覆盖度直接决定 Linux 上可玩的游戏范围；跟随 Wine 12.0 节奏升级，是游戏兼容性与性能改善的必要条件。

Mesa 27.0 合入 LLVMpipe 的 AVX-512 支持：纯 CPU OpenGL 渲染吃上 512 位向量
计算 compute
上月报道过的 LLVMpipe AVX-512 工作已于 11 月 23 日合入 Mesa 27.0-devel（MR !45279）。这项由 David Airlie 多年前发起、一度搁置的工作，近期借助 GPT Terra 与 Astra 两个 AI 模型协助才得以完成，不过作者手头没有现代 AVX-512 处理器可做实测。本次合入的核心是 512 位宽的 LP_NATIVE_VECTOR_WIDTH，这是软件 OpenGL 驱动正确利用 AVX-512 加速的最后一块拼图。合并请求中未提供性能数据，实际收益有待在 Zen 4/5 或 Xeon 等支持 AVX-512 的平台上验证。
关注理由：LLVMpipe 是无 GPU 环境（服务器、CI、远程桌面）下的重要 OpenGL 后备；补齐 AVX-512 可让这类场景的图形计算受益于现代 CPU 的向量宽度，同时也提供了一个 AI 辅助完成遗留内核/驱动移植的有趣案例。

Zstandard 1.6 发布：AArch64 解压提速、SVE2/RVV 向量优化，修复多线程压缩问题
计算 compute
距上一版 1.5.7 约一年半后，Meta 于 11 月 23 日发布 Zstandard 1.6.0。这是自 2025 年 2 月以来的首个大版本：64 位 ARM（AArch64）解压更快，支持 SVE2 的 CPU 压缩更快，并包含其他 Neon / SVE2 优化；RISC-V 侧则带来基于 RVV 向量扩展的性能优化。修复方面涉及多线程（解）压缩问题、32 位平台问题，以及 STD_compressSequences() 与 ZSTD_compressSequencesAndLiterals() 中可能出现的内存损坏；此外还有命令行参数调整与少量 API 变化。Meta 表示新算法优化的重心正转向内容感知压缩项目 OpenZL，不同 CPU 上的 Zstd 基准结果将陆续公布。
关注理由：Zstd 是内核、文件系统、包管理与日志链路的基础压缩库；AArch64/RISC-V 向量优化会直接影响服务器与边缘设备的压缩吞吐，内存损坏修复也值得发行版尽快纳入。
