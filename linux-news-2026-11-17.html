Intel GPU D270（Xe3P「Crescent Island」）晒性能：金融基准达 RTX PRO 6000 Blackwell 的 1.92~5.9 倍
图形 GPU
超算 2026（SC26）周期间，Intel 发文介绍 Intel GPU D Series「Crescent Island」的硬件规格、相对性能与开源软件策略。旗舰型号 GPU D270 基于 Xe3P 架构：32 个 Xe 核心、256 个 XMX 引擎、原生 FP4~FP64 支持且 DP 为全速率，板载 160GB LPDDR5X、可扩展至 480GB，350W PCIe 5.0、风冷。性能方面，Intel 给出了对比 NVIDIA RTX PRO 6000 Blackwell 的金融服务基准：吞吐为其 1.92~5.9 倍（限定范围的有限基准集）。开源侧延续一贯路线：Xe 内核驱动的 Crescent Island bring-up 与面向 OpenCL/Level Zero 的 Compute Runtime 栈均已持续数月推进。
关注理由：D270 主打 HPC/AI 推理的高内存容量路线（160GB→480GB），与 NVIDIA 形成差异化竞争；对 Linux 图形/计算方向而言，Xe3P 驱动上游化进度与跨厂商性能对标数据都值得跟踪。

MRDIMM 8800 vs 12800 MT/s 实测：EPYC「Venice」整体只差约 2%，但 HPCG 差 26%
计算 compute
Phoronix 补测 EPYC 9686F 2P 在 MRDIMM-8800 速率下的表现（上周 EPYC 9006 SP7 发布评测用的是 MRDIMM-12800，目前 12800 条在零售渠道还买不到，8800 一代 64GB 单条就要 3~4 千美元）。结论：几十项基准里整体平均只差约 2%；差距最大的负载是 HPCG 26%、libxsmm 11~25%（随矩阵大小）、BRL-CAD 20%、OpenFOAM CFD 5~17%、WRF 11%。即便降到 8800 MT/s，EPYC 9686F 仍领先 EPYC 9005 Turin（DDR5-6400）与 Intel Xeon 6980P（MRDIMM-8800）。
关注理由：内存涨价周期里「12800 买不到、值不值」是服务器选型的现实问题：整数/多数负载几乎无感，但访存敏感型 HPC/科学计算负载差异显著——按负载类型选内存档位比看均值更有意义。

LLVM 启动退役 AMD R600/TeraScale 后端：Radeon HD 2000~6000 的编译时代落幕
图形 GPU
AMD 上海编译团队的 Harrison Hao 向 LLVM 社区发出 RFC：弃用并移除 R600（TeraScale）后端——即曾经服务 Radeon HD 2000 到 HD 6000 系列 GPU 的代码生成后端。移除理由：Mesa 的 R600g 驱动早已转用 NIR 路线、不再走 LLVM 后端；Clover OpenCL 也已从主线 Mesa 移除（由 Rust 编写的 Rusticl 取代），该后端已无已知用户，却让现代 AMDGPU 后端每次改动都要顾及遗留分支、lit 测试也需持续维护。RFC 只涉及 TeraScale 时代硬件，GCN 及之后走 AMDGPU 后端的显卡不受影响；目前社区尚未出现反对声音。
关注理由：TeraScale 后端退役是 Linux 图形栈「去包袱」的标志性一步：R600g 驱动本身仍留在 Mesa（NIR 路线），只是编译链简化；对维护 GPU 编译后端的人来说是 AMDGPU 后端减负的好消息。

Rust Nightly 默认启用并行前端：编译提速测试数月后推进 stable
计算 compute
Rust 编译器的后端早已多线程，但前端一直默认单线程执行。现在 Rust 项目开始在 Nightly 频道默认启用并行前端，先在 nightly 上收集数月测试结果，再逐步把该默认值推进到 stable。并行化能力其实早已存在（原计划 2024 年稳定化），只是默认关闭；官方给出的基准显示启用后按 2/4/8 线程都能取得可观的构建提速。前端线程数可通过 --jobs-frontend= 选项控制，团队还会继续优化前端并行化性能。
关注理由：Rust 已是 Linux 内核与大量基础软件的构建依赖，前端并行化对 CI/本地构建时长是普适性收益；对做构建性能优化（含内核 Rust 子系统）的团队值得尽早评估。

Purism 公布 Librem 5 v2：转投 RISC-V（SpacemiT K1 八核），2028 年中才交付
显示 display
历经多轮跳票的 Librem 5 项目重启：Librem 5 v2 弃用 NXP i.MX ARM SoC，改用八核 RISC-V 的 SpacemiT K1。配置较一代升级：内存 3GB→8GB，存储 128GB + SD 卡槽，双 SIM，5.7 吋 720×1440 屏幕，保留硬件 kill switch、可更换 4500mAh 电池、13MP 后置/8MP 前置摄像头。不过 K1 基于 RVA22 profile（而非已成 Linux 世界新基线的 RVA23）。目标2028 年中规模化交付；众筹需在 2 月 15 日前达到 2500 台预订，预订价 1599 美元。
关注理由：主流 Linux 手机厂商直接转 RISC-V 是终端生态的又一个信号；对关注 RISC-V 软件栈（mainline 内核支持、RVA22 vs RVA23 分歧）的人来说值得观察，但 2028 年时间线与 K1 性能都注定小众。
