Intel 与 AMD 联合宣布围绕 PyTorch/oneDNN 展开软件优化协作：ZenDNN 改进合入上游
计算 compute
Intel 长期为自家硬件调优 oneDNN 神经网络库（已被 PyTorch 等 AI 框架采用）；AMD 则维护 oneDNN API 兼容的下游分支 ZenDNN，针对 Zen 处理器设计做优化。10-20 两家联合宣布：将围绕 oneDNN for PyTorch 展开协作，把 AMD Zen 侧的改进推进上游 oneDNN。
换言之，AMD 从「自己养分支」转向「与 Intel 共建同一个上游」，x86 阵营在 PyTorch CPU 路径上的优化将收敛到一条主线。
关注理由：两大 CPU 厂商在 AI 软件栈上从「各养分支」走向「共同上游」是少见的一幕：碎片化减少后，PyTorch 在 x86 服务器上的 CPU 推理/训练优化将同时吃到 Intel 与 AMD 的红利，用户无需在 ZenDNN 与 oneDNN 之间做选择题。
对关注 AI 推理软件栈的同学，这也是观察「竞合模式」的样本——竞争关系不妨碍共享基础库；后续值得跟踪 ZenDNN 的核心优化（如 AMX/AVX-512 路径）以什么形式落进上游。

Dynamic PAMT 合入 Linux 7.4：显著削减 Intel TDX 服务器的内存开销
计算 compute
在 Linux 7.4 合并窗口开启后的首批 PR 中，Dynamic PAMT 正式合入。
背景：Intel TDX（Trust Domain Extensions）机密计算引入了 PAMT（Physical Address Metadata Table）——按 4KB 粒度为客户机物理内存维护页元数据，代价是服务器需预留一笔不小的内存；但现实中很多 TDX 服务器上并发虚拟机并不多、大部分内存并未真正被 TDX 使用，全量 PAMT 变成纯浪费。
Dynamic PAMT 的思路：仅在实际需要时才为对应区域分配/填充 PAMT 页，把静态的「全量预付」变成按需付费，在 VM 数量少的 TDX 服务器上大幅降低内存开销。报道特别指出，在当下内存价格高企、供货紧张的背景下，这笔节省对现代 Intel Xeon 服务器相当可观。
关注理由：机密计算的「内存税」是 TDX 落地的主要阻力之一，Dynamic PAMT 把这笔税从固定成本变成可变成本，云厂商按需启停 TDX 虚拟机的经济性明显改善——这与 10-18 期「Intel TDX 不需要那么多缓存刷新」一起构成 TDX 减负的两条线（运行时开销 + 常驻内存）。
对关注服务器平台与虚拟化安全的同学，Linux 7.4 值得作为 TDX 特性版本的观察点。

COSMIC Epoch 1.11 发布：xdg-dialog-v1 Wayland 协议 + 混合图形 GPU 选择修复
显示 display
System76 发布 Rust 编写的桌面环境 COSMIC Epoch 1.11（距 1.10 约两周）：COSMIC 合成器新增 xdg-dialog-v1 Wayland 协议支持——模态对话框不再被其他窗口遮挡，并包含一批合成器修复。
混合图形：COSMIC 应用库与 pop-launcher 现在会在混合显卡系统上确保使用正确的 GPU（游戏不再误跑核显/独显）。
其他：触控板新增 tap-and-drag 与 drag lock 选项；libcosmic 修滚动条 padding、文本输入不再吞 Escape 键；COSMIC Edit 支持 JSON 的 MIME 关联；合成器在无显示器连接时清理遗留窗口、屏幕键盘改走私有 D-Bus 信号（修复与其他输入法配合时的虚拟键盘问题）。1.11 属维护性质发布（meta 仓库仅 3 个 commit，重指向约 15 个子项目）。
关注理由：两条值得显示栈同学留意：xdg-dialog-v1 是较新的 Wayland 模态对话框协议，COSMIC 成为又一落地实现（合成器侧参考实现多了一个）；混合图形的 GPU 选择（游戏走 dGPU、常驻应用走 iGPU）则是 PRIME/offload 场景的老大难，COSMIC 把它做进应用库与 launcher 层而非只靠环境变量，思路可对照 zeus 平台的多 GPU 调度设计。
Rust 桌面第三极保持约两周一个点的快节奏迭代，稳定性补齐速度可观。

KDE Plasma 6.8.1 发布：数十项修复，6.8 进入稳定化
显示 display
继上周 Plasma 6.8 正式发布（KDE 30 周年版本）后，Plasma 6.8.1 点版本今日发布，带来数十项缺陷修复，覆盖 6.8 新引入特性（commit-timing、多 GPU/多屏改进等）的稳定化收尾。
另据 Phoronix 报道，KDE 开发者已开始向 Plasma 6.9 推进新特性：包括新的天气小部件与屏幕键盘。
关注理由：6.8 是近年在图形/显示侧动作最大的一版（KWin commit-timing 协议、vRAM 优化、多 GPU/多屏增强、发布前最后一刻修 NVIDIA 专有驱动平铺卡顿），6.8.1 的修复清单可以看作这批新路径的「踩坑实录」——对在做 Wayland 合成器/显示路径验证的同学是现成的回归点参考。
跟踪 Plasma 6.8 部署的发行版（如即将跟进的各发行版滚动更新）也可据此判断升级窗口。

Linux Foundation 研究估计：约 25% 的新开源 PR 是低质量 AI slop
内核 kernel
Linux Foundation 发布关于生成式 AI 对开源软件开发影响的新研究，核心结论之一：约 25% 的新开源软件 pull request 属于 AI slop（低质量 AI 生成内容）。
这与内核社区近期的多条线索互相印证：Linux 7.4 引入 TAINT_FORCED_BIND 应对 AI agent/bot 对不现实驱动/硬件组合的大规模 fuzzing「攻击」；EDAC 子系统因 AI 生成修复的噪音泛滥而弃用一批旧驱动；维护者峰会后内核一度讨论强制 AI「Assisted-by」标签、后取消强制。
负面之外另一面：Linus 用 Claude Code 的内核优化、Google Sashiko 的 19 万次评审等，AI 在内核开发中的有效贡献同样在快速增加。
关注理由：这是AI 对开源生态冲击的首批系统性量化数据：1/4 的新 PR 是噪音，意味着维护者审阅负担显著加重，也解释了内核近期一系列「防 AI 噪音」机制（taint 标记、子系统收缩、标签讨论）为何密集出现。
对团队代码质量把控有直接借鉴：AI 辅助编码在提效的同时，评审带宽是新的稀缺资源——我们自己的 RDMA 代码评审流程也值得提前设防（如 AI 生成代码的标注与重点审查清单）。

17k 行新 Rust 内核代码进入 Linux 7.4：Zerocopy 库 vendored 更新领衔
内核 kernel
Rust for Linux 负责人 Miguel Ojeda 发出面向 Linux 7.4 的 Rust PR，本轮规模较大：约 1.7 万行新 Rust 代码进入内核。
体量主因：更新 vendored 的 Zerocopy 库，以及更新内核中的其他 Rust crates。Zerocopy 提供「在字节缓冲与结构体之间安全零拷贝转换」的抽象，是 Rust 驱动与协议解析的地基组件之一。连同 7.4 里 Nova 驱动的大幅扩建（DRM Rust 变更、VRAM 管理、TLB 刷新等），Rust 侧在 7.4 周期的存在感明显上升。
关注理由：Rust for Linux 的代码量增长曲线值得关注：vendor 第三方 crate（如 Zerocopy）标志着内核 Rust 生态从「手写基础设施」转向「复用 crates.io 成熟库」的阶段，这对后续 Nova（NVIDIA）、Tyr（Arm Mali）等 Rust GPU 驱动的开发效率是实质利好。
对做 NPU/RDMA 驱动的同学，Rust 驱动栈的可复用组件（零拷贝转换、设备抽象）未来可能同样适用于加速器驱动开发，值得持续跟踪。
