GXVK：3Dfx Glide API 在 Vulkan 上重生，D7VK 2.4 同步发布
图形 gpu
D7VK（Direct3D 7/6/5/3 on Vulkan）在一个月前宣布进入维护模式后意外发布 2.4 版，更大的惊喜是随之亮相的 GXVK 项目：把 1990 年代 3Dfx Voodoo 卡的 Glide API 实现在 Vulkan 之上。GXVK 由 D7VK 贡献者 CkNoSFeRaTU 开发，通过 fork DXVK（D7VK 亦 fork 自 DXVK）实现，目标是将 3Dfx 发布的全部三个 32 位 Glide 变体补齐，开发以 Wine/Linux 为重点；目前为早期 alpha（v0.1），已可跑通《Pandemonium 2》《Incubation: Time Is Running Out》等 Glide 独占游戏。D7VK 2.4 本体则 rebase 到最新上游 DXVK（带入 present timing）、默认禁用后缓冲拉伸并支持保持宽高比（利好 Wayland）、改进 present interval 与 VSync 状态传播（修 Re-Volt、3DMark 2000 显示问题）。
关注理由：Glide 是 OpenGL/D3D 普及前的传奇图形 API，一批 Glide 独占游戏此前没有开源现代化路径；DXVK 系「老 API → Vulkan」的实现思路对理解兼容层架构与游戏 Preservation 都有参考价值。

VKD3D-Proton 3.1 发布：3.2 大改版前最后一个稳定点
图形 gpu
Valve 的 Hans-Kristian Arntzen 标签发布 VKD3D-Proton 3.1：DX12→Vulkan 转换层（Proton 与 Steam Deck 的核心组件）进入 3.2 大版本前最后的「稳定」检查点。新特性：VK_EXT_descriptor_heap 描述符堆支持（因驱动质量顾虑暂未默认启用，master 分支即将切换，3.2 计划默认开启）；KHR_opacity_micromap 支持并暴露 DXR 1.2 光追；Shader Model 6.9（Shader Execution Reordering + long vector，当前仅 NVIDIA 点亮）；更多 NVAPI intrinsics、AgilitySDK 619 特性、view instancing 默认启用。性能侧：ClearUAV 走 vkCmdClearColorImage/FillBuffer 快路径、优化病态 COPY→RESOURCE→COPY 屏障模式、减少 Present() 遮挡检查的合成器往返、RTAS 构建命令批量提交（部分场景光追性能大幅提升）。修复侧：Steam Frame 成受支持平台（含 aarch64 构建）、AMD_anti_lag 实现简化并修帧归因问题、low_latency2 对齐规范第 3 版。
关注理由：descriptor heap 是 DX12 绑定模型的现代化改造，默认启用后将显著降低 CPU 绑定开销，是 3.2 的架构级变化，值得提前在多驱动上压测；Steam Frame/aarch64 支持也说明 Valve 在为 ARM VR 设备铺路。

Hyprland 0.57 发布：Compiz 式摇晃窗口回归 Wayland
显示 display
Wayland 合成器 Hyprland 0.57 发布，带来致敬二十年前 Compiz/Beryl 时代的 wobbly windows（摇晃窗口）效果——以窗口变换器（window transformer）实现，可用 no_wobble 窗口/工作区规则关闭。其他亮点：可切换的模糊变体（blur variants）、工作区共享（Hyprland 与 XDPH 同时实现，浏览器/会议软件共享屏幕时可直接选择某个工作区作为源）、scene composition 渲染管线、硬件支持时默认启用 FP16 渲染（削减模糊等特效的内存带宽）、新增 xx-hotkey-v1 全局快捷键协议、OpenBSD 构建支持推进中；旧版 .conf 配置彻底弃用、全面转向 Lua 配置。修复超百项，按 PR 数计是 Hyprland 史上最大版本之一；Omacom 基金会（Omarchy 背后）成为其独家赞助方。
关注理由：FP16 渲染与 scene composition 是实打实的渲染效率改进；升级前必须先完成 Lua 配置迁移，否则无法启动；独家赞助模式对独立桌面项目的可持续性也是个值得关注的新样本。

System76 发布 Thelio Prime：11 升 AMD 迷你 Linux 工作站
计算 compute
System76 预告新款 Thelio Prime 迷你台式机：11 升体积（288×148.9×281.9mm），11 月 18 日上市、起价 1599 美元。CPU 为 AMD Ryzen 9000 系列（最高 Ryzen 9 9950X / 9850X3D），显卡可选 Radeon 核显或 AMD/NVIDIA 独显（最高 RTX 5070）；内存最高 96GB DDR5，双 M.2 槽最高 8TB NVMe（一条 PCIe 5.0 + 一条 PCIe 4.0）。CPU 与 GPU 采用独立散热腔设计，机箱为铣削不锈钢 + 铝合金、免工具磁吸侧板；整机在科罗拉多丹佛工厂制造组装。预装 Pop!_OS 24.04 LTS（COSMIC 桌面）或 Ubuntu 24.04 LTS，前置 USB-C、后置 2.5GbE / Wi-Fi 6E / HDMI 2.1。
关注理由：介于 Thelio Major/Mira 与传统 mini PC 之间的新形态，双散热腔让小机箱也能装 RTX 5070 级独显；对需要预装 Linux、兼顾体积与可维护性的工作站场景是新的选型项，后续可关注 Phoronix 实测。

XCB 联合作者首写 Wayland 客户端，盛赞协议设计
显示 display
X.Org 老牌开发者、X 协议 C 语言绑定 XCB 的联合作者 Jamey Sharp，近日首次编写 Wayland 客户端后在 Mastodon 上盛赞其设计：「我能看到 Wayland 设计者从 X、乃至从 XCB 吸取的每一课的影响，真心对 Wayland 协议的设计印象深刻」。他写了 300 多行 Rust（刻意不用 wayland-client crate 的 helper，体验原始协议），实现开窗口 + 黑白闪烁并测量时序统计。针对「Wayland 打开个窗口要写太多代码」的常见抱怨，他的回应是：Wayland 是「为把难事做成而设计的协议，不是把易事变简单」——想做简单的事请用 GTK/Qt/SDL 等工具包；低层协议保持最大灵活性，易用性属于上层抽象，这个复杂度取舍是正确的，因为「砍掉任何一步，就砍掉了处理更复杂场景的能力」。
关注理由：来自 X11 阵营核心开发者的背书，是对 Wayland 协议设计哲学（低层灵活 + 上层封装）最有分量的注解之一；「协议为难点而生、易用性交给工具链」的分层思路对任何协议/接口设计都有借鉴意义。
