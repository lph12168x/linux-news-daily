Linux 7.4-rc4 发布：Linus 称「大得惊人」，驱动改动占一半
内核 kernel
11 月 22 日（美东周日），Linus Torvalds 发布 Linux 7.4 的第四个候选版本，并罕见地用一句反讽开场：「Sunday afternoon, and -rc4 is out. Big. Surprise.」。他解释说，小修小补散布各处，驱动恰好占了一半——GPU、网络照例在列，还包括 USB、IIO、NVMe、声卡等；另一半是核心内核、内存管理、文件系统、网络、自测与架构更新。继约 2 万次提交的「史上最大合并窗口」之后，rc3 还被形容为「普通一周」，rc4 又明显变大，Linus 直言「好日子回不来了」，请大家继续测试。本轮中值得注意的具体变化包括：NVMe 命名空间改为并行删除（每次删除约 20ms 的 RCU 宽限期可重叠，64 个命名空间的控制器拆除不再超过 1 秒）、登记 Intel Coral Rapids（服务器）与 Razor Lake（客户端）的 CPU model ID（面向 2028 年及以后产品，为 7.5 起的多轮驱动补丁铺路），以及把 Granite Rapids D 加入 SNC 支持表。正式版预计 12 月底发布，是否列为 LTS 仍未定。
关注理由：7.4 是 2026 年最后一个大版本，rc4 的体量反映 AI/LLM 辅助挖 bug 与补丁带来的开发强度；其中的 GPU 修复、下一代 CPU ID 与存储控制面优化，都会直接影响后续图形/计算驱动的上游节奏。

AMD 为 Linux 7.5 再送一轮 AMDGPU/AMDKFD 更新：DCN6 解锁 HDCP，HDMI 2.1 / VRR 持续修
图形 GPU
AMD 本周发出 amd-drm-next-7.5-2026-11-19 系列补丁，为 7.5 合并窗口继续准备 AMDGPU 内核图形驱动与 AMDKFD 计算驱动更新；本轮以修复为主。最受关注的是下一代 RDNA 5 显卡所用显示 IP Display Core Next 6（DCN6）的进一步使能，包括开启 HDCP 内容保护支持；同时 DCN 4.2 / 4.6 拿到一批修复。清单还覆盖新近 HDMI 2.1 引入与 VRR 支持的持续修错、GPUVM、UserQ、PSR、Freesync、背光、DPMS、SR-IOV、PSP 15 更新、DC 水印重构、多 XCC 部件的着色器修复、模块加载失败回滚等；AMDKFD 侧修正 SVM 与初始化顺序，老 Radeon 驱动补上 VBIOS 解析边界检查。DRM 新补丁截止时间约在两周后，Linux 7.5 合并窗口预计 12 月底开启。
关注理由：DCN6 是 RDNA 5 显示栈在主线内核成形的关键节点，HDCP、HDMI 2.1 与 VRR 的成熟度直接决定新卡上市时的桌面体验；本周修复密度也说明 AMD 正赶在合并窗口前集中收敛。

Intel 让 PSR2 / Panel Replay 兼容 Pipe Joiner：Linux 7.5 支持 8K 与 4K@240Hz 下省电
显示 display
Intel 工程师 Mika Kahola 解决了驱动限制：启用 pipe joiner 时也能使用 PSR2 与 Panel Replay 省电特性，代码已随本周的 drm-intel-next pull request 提交进 DRM-Next，面向 Linux 7.5。Pipe joiner 允许多条内部显示管共同驱动一块超高分辨率或高刷新率面板，突破单条显示管的限制；四管 ultra joiner 配置可支持 8K 与 4K@240Hz。但此前一旦启用 joiner，PSR2（eDP 只刷新画面变化区域）与 Panel Replay（eDP/DP 在画面不变时由面板自刷新、或只做选择性更新以降低带宽与功耗）都无法工作。本周 PR 同时还包含代码清理、IRQ 处理优化与多项驱动修复。
关注理由：高分辨率、高刷新率笔记本是最需要省电也最容易撞上显示管限制的品类；把 PSR2/Panel Replay 与 joiner 打通，意味着 8K / 4K@240Hz 配置不再需要在画质与续航之间二选一。

Linux 7.5 把 GEM/TTM 的 mmap 偏移范围从 1TB 提到 8TB：为多 GPU 大显存铺路
图形 GPU
Intel GPU 驱动工程师 Matthew Auld 的补丁已随 drm-misc-next 进入 DRM-Next，将在 Linux 7.5 把内核图形驱动中 GEM/TTM buffer object 的假 mmap 偏移范围从 1TB 扩大到 8TB。动机来自多 GPU 大显存场景：跨设备、跨进程的 P2P dma-buf 导入会耗尽现有 1TiB 的 64 位偏移区间，导致 BO 创建或 PRIME import 以 -ENOSPC 失败；又不能直接跳过导入 sg buffer 的偏移分配，因为 Intel compute-runtime 等用户态仍会查询所导入 host dma-buf 的 mmap_offset。做法是把 DRM_FILE_PAGE_OFFSET_SIZE 提到 SZ_8T，仍严格低于 panthor 保留的 DRM_PANTHOR_USER_MMIO_OFFSET_32BIT（1ULL << 43），也处于 32 位兼容 mmap2 的 16TiB pgoff 上限之内。外界普遍认为此举与 Intel Crescent Island / GPU D 系列（单卡最高 160GB LPDDR5X）有关。
关注理由：显存容量与多卡 P2P 正在把 DRM 的旧假设推到极限；把偏移空间一次性放大 8 倍，是让 160GB 级加速卡与 compute-runtime 在主流内核上正常共存的底层基础设施改动。

AMDXDNA 驱动在 Linux 7.5 升到 1.0：新增 NPU10 / NPU11（NPU3 rev 0x14 / 0x15）
计算 compute
面向 Ryzen AI NPU 的 AMDXDNA 加速器驱动将随 Linux 7.5 宣告 1.0 版本，从此前的 v0.10 直接跃升。Linux 7.5 预计 2027 年第一季度发布，1.0 与「首个正式支持 AIE4 设备的版本」对齐——AIE4 被认为是未来 Zen 6 Ryzen AI 客户端 SoC 所用 IP。同一批补丁还加入 NPU10 / NPU11 设备支持，两者都是基于 NPU3 的修订版 0x14 与 0x15；官方未说明对应产品，外界推测是某些 Zen 5 SoC 衍生型号。补丁本周经 drm-misc-next 送入 DRM-Next。文章也回顾了 Ryzen AI NPU 的 Linux 生态：直到今年早些时候 FastFlowLM 与 Lemonade 本地 AI 服务器介入后才真正可用于大模型推理，而 Unsloth Desktop 也刚在前一天宣布支持（含 Linux 版本）。
关注理由：从 0.x 到 1.0 加上新设备 ID，是 AMD NPU 上游支持走向稳定的信号；对关注端侧推理与加速器驱动的人来说，内核版本与用户态（Lemonade / FastFlowLM / Unsloth）的同步成熟比单次性能提升更关键。

Intel Linux NPU 驱动 1.39.1 发布：正式支持 Nova Lake 第六代 NPU
计算 compute
Intel 于 11 月 21 日（周四）发布 Linux NPU Driver v1.39.1。本次点版本更新的主要内容是新增 Nova Lake 平台支持，对应其第六代 NPU IP；这依赖此前已上游进 IVPU 加速器驱动的内核侧使能补丁。发布说明同时建议，Nova Lake NPU 用户搭配尚未发布的 OpenVINO 2026.5 AI 工具套件使用。除此之外本次没有别的功能变化，可从 Intel 的 GitHub release 页面下载。
关注理由：继内核侧 IVPU 支持合入之后，用户态驱动跟进意味着 Nova Lake NPU 的软件栈开始具备可用性；对评估 Intel 下一代端侧 AI 加速能力的人来说，OpenVINO 版本搭配是部署时需要留意的细节。

Vulkan 1.4.369 加入 AMD 实验性扩展：多级加速结构降低光追构建开销与显存占用
图形 GPU
11 月 20 日发布的 Vulkan 1.4.369 除两周积累的 API 澄清与修正外，最重要的是引入 AMD 的实验性厂商扩展 VK_AMDX_multi_level_acceleration_structure：允许在光追加速结构（AS）层级中额外增加最多两级 instance，以更细的粒度控制大型世界哪些部分需要重建或更新，并借助几何复用降低显存占用。规范文档指出，开发者此前被迫限制光追世界的复杂度，两大瓶颈是 AS 构建/更新耗时与内存占用；多级实例化可以把顶层结构建在若干中间层结构的实例上，而不是把全部底层实例「摊平」后逐一挂接；同时，可用刚体变换驱动的动画几何也不必为了塞进两级 BVH 而反复复制。扩展目前仍属实验性质，因此带有 AMDX 前缀。
关注理由：光追场景规模化的主要障碍正是 AS 重建成本与内存足迹；如果多级加速结构最终进入核心规范，将直接影响游戏与渲染引擎组织动态场景的方式，值得图形开发者提前关注。

AMD 把自适应背光调制集成进 GNOME Mutter：按画面内容动态调背光省电
显示 display
11 月 20 日，支持 Adaptive Backlight Modulation（ABM） DRM/KMS connector 属性与 content-adaptive API 的补丁合入 GNOME 合成器 Mutter，由 AMD 为现代 Ryzen AI 笔记本贡献。ABM 的原理是在深色或低亮度画面下降低面板背光并在图像侧补偿，用部分色彩精度换功耗，对电池续航尤其有意义；AMDGPU 内核驱动此前已为支持的 eDP 面板暴露该 connector 属性，这次补的是合成器一侧。按合并说明，content-adaptive 作为 MetaBacklight 上的一个等级（索引 0..max，默认 0 为关闭）在下一帧写入 KMS；Mutter 不自行选择等级，而由 shell 在进程内调用 C API（无 D-Bus 接口）；首帧写入时会从驱动的 sysfs 接口接管该属性，关机时不交还，留给通用 DRM reset 处理。详见 Mutter 的 MR !5192。
关注理由：这是把内核已有的显示省电能力接入主流桌面合成器的典型案例：Linux 笔记本的屏幕功耗优化长期落后于 Windows，此类上游集成会让 Ryzen AI 平台的续航改进真正落到用户手里。
